## §A Header

Lane CD24 đảm bảo **tính nhất quán hiển thị format** (date/number/currency/timezone) trong `apps/erp-web` so với SSOT `display_formats`. Logistics-aware: VND không decimal (TT 78/2021/TT-BTC), CNY 2 decimal, BOL number ISO format, container number ISO 6346, phone VN format.

**Vì sao quan trọng:**
- Date format không nhất quán → user confusion (DD/MM/YYYY vs MM/DD/YYYY trộn)
- Currency hardcoded `₫` symbol thay vì `<FormatCurrency code="VND" />` → khó switch locale CN/EN
- VND có decimal `1,234,567.50 VND` → vi phạm TT 78/2021/TT-BTC (e-invoice VN)
- Timezone naive `new Date()` → bug khi server timezone ≠ user timezone (server UTC, user GMT+7)
- BOL/container number format drift → fail VNACCS validation hoặc carrier integration

### Step CD24.2 — Date format inconsistent (DATE_FORMAT_INCONSISTENT)

> Hardcoded date format string không qua formatter component.

**Logic:**
1. Iterate `fe-component-graph.nodes[]` filter file_path ngoài `exclusions.date_format[]`
2. Grep patterns:
   - `format\(\s*['"]([^'"]+)['"]\s*\)` (dayjs/date-fns format calls)
   - `toLocaleDateString\(` (raw JS method)
   - `new Date\(.*\)\.toString\(\)` (raw conversion)
   - `moment\(.*\)\.format\(['"]([^'"]+)['"]\)` (legacy moment)
3. Extract format string từ capture group
4. Cross-ref với `DATE_FORMAT`:
   - Format string KHÁC `DATE_FORMAT` declared → DATE_FORMAT_INCONSISTENT (severity HIGH)
   - Raw method usage không qua `<FormatDate />` component → DATE_FORMAT_INCONSISTENT
5. Skip components có comment `// @format-exception:date`

**Signal payload:**
```json
{
  "kind": "DATE_FORMAT_INCONSISTENT",
  "severity": "HIGH",
  "category": "VIOLATION",
  "rule_id": "UXFMT-CD24-001",
  "message": "Component OrderList dùng date format 'MM/DD/YYYY' khác với SSOT declaration 'DD/MM/YYYY'",
  "affected_entities": ["OrderList"],
  "affected_files": ["apps/erp-web/components/order-list.tsx"],
  "evidence": [{"file": "apps/erp-web/components/order-list.tsx", "line": 34, "snippet": "dayjs(order.createdAt).format('MM/DD/YYYY')", "expected_format": "DD/MM/YYYY"}],
  "suggested_action": "Thay bằng <FormatDate value={order.createdAt} /> hoặc dayjs(...).format('DD/MM/YYYY')"
}
```

### Step CD24.3 — Number format inconsistent (NUMBER_FORMAT_INCONSISTENT)

> Hardcoded toLocaleString/toFixed/Intl.NumberFormat không qua formatter.

**Logic:**
1. Iterate components, Grep:
   - `\.toLocaleString\(['"](vi-VN|en-US|zh-CN|en-GB)['"]` (locale string call)
   - `\.toFixed\(\d\)` (decimal precision call)
   - `Intl\.NumberFormat\(` (raw Intl)
   - `Number\(.*\)\.toLocaleString\(\)` (chained)
2. Cross-ref `display_formats.number.{thousands_separator,decimal_separator,decimal_places}`:
   - Component dùng locale khác config → NUMBER_FORMAT_INCONSISTENT (severity SHOULD)
   - Hardcoded `.toFixed(N)` không qua `<FormatNumber />` → NUMBER_FORMAT_INCONSISTENT
3. Skip components có comment `// @format-exception:number`

**Rule ID:** `UXFMT-CD24-002`

### Step CD24.4 — Currency format inconsistent (CURRENCY_FORMAT_INCONSISTENT)

> Hardcoded currency symbol hoặc thiếu currency code.

**Logic:**
1. Iterate components, Grep:
   - Literal currency symbols: `['"]₫['"]|['"]\$['"]|['"]¥['"]|['"]VNĐ['"]|['"]VND['"]|['"]CNY['"]|['"]USD['"]`
   - `\.toLocaleString\(.*currency.*\)` calls
   - Format pattern `\$\{amount\}\s*(₫|VND|đ|\$|USD|¥|CNY|元)` (string template literal)
2. Cross-ref `display_formats.currency.{vnd,cny,usd}`:
   - Component KHÔNG dùng `<FormatCurrency code="VND" />` wrapper → CURRENCY_FORMAT_INCONSISTENT (severity HIGH)
   - Symbol literal mà KHÔNG kèm code → CURRENCY_FORMAT_INCONSISTENT
3. Skip components có comment `// @format-exception:currency` hoặc trong `exclusions.currency_display[]`

**Rule ID:** `UXFMT-CD24-003`

**Note:** Severity HIGH vì multi-currency VND/CNY/USD critical cho logistics Việt-Trung.

### Step CD24.5 — Timezone drift (TIMEZONE_DRIFT)

> Naive datetime hoặc timezone không declared.

**Logic:**
1. Iterate components, Grep:
   - `new Date\(\)` standalone (naive — server vs client timezone risk)
   - `Date\.now\(\)` raw (unix timestamp without timezone context)
   - `dayjs\(\)` không kèm `.tz(...)` hoặc `.utc()`
   - `moment\(\)\.local\(\)` (local timezone assumption)
2. Cross-ref `DATETIME_TIMEZONE` (vd `Asia/Ho_Chi_Minh`):
   - Component KHÔNG dùng timezone-aware wrapper → TIMEZONE_DRIFT (severity SHOULD)
   - Date computation cross-day boundary risk (vd `.startOf('day')` không tz) → TIMEZONE_DRIFT
3. Skip server-side files (page server components, server actions có `'use server'`)

**Rule ID:** `UXFMT-CD24-004`

### Step CD24.6 — VND decimal present (VND_DECIMAL_PRESENT) ★

> VND amount hiển thị có decimal places vi phạm TT 78/2021/TT-BTC.

**Logic:**
1. Iterate components, Grep patterns:
   - `['"]VND['"]` literal near `\.toFixed\([1-9]\)` (vd `toFixed(2)`)
   - `decimal_places:\s*[1-9]` near currency=VND context
   - Format string `{amount}\.\d+\s*(₫|VND)` (số có decimal kèm VND)
2. Cross-ref `VND_DECIMAL` (PHẢI = 0):
   - Component dùng `decimal_places ≥ 1` cho VND → VND_DECIMAL_PRESENT (severity **HIGH** — compliance violation)
3. Special case: amount field validation level — flag cả backend display nếu component show VND field từ API

**Rule ID:** `UXFMT-CD24-005`

**Note:** Severity HIGH vì TT 78/2021/TT-BTC bắt buộc — invoice xuất ra phải tròn VND. Compliance gate.

```bash

    "scan_duration_sec": ($scan_duration | tonumber),
    "signals": $signals,

      },
      "category_breakdown": {
        "MISSING_INVARIANT": ([$signals[] | select(.category == "MISSING_INVARIANT")] | length),
        "VIOLATION": ([$signals[] | select(.category == "VIOLATION")] | length),
        "GAP": ([$signals[] | select(.category == "GAP")] | length),
        "RECOMMENDATION": ([$signals[] | select(.category == "RECOMMENDATION")] | length)

      "modules_covered": $modules_covered,
```

```bash
# T1
for f in signals.json CD24-ux-display-format-report.md lane-status.json; do
  [ -f "$LANE_DIR/$f" ] || die "E044" "Output missing: $f"
done

# T2

LANE_VAL=$(jq -r '.lane' "$LANE_DIR/signals.json")
[ "$SCHEMA" = "signals-v1" ] || die "E044" "Schema mismatch"

[ "$FP_TOTAL" = "$FP_UNIQUE" ] || die "E044" "Fingerprint collision"

# T3 — Rule ID format + severity compliance
INVALID_RULES=$(jq -r '[.signals[] | select(.rule_id | test("^UXFMT-CD24-[0-9]{3}$") | not) | .rule_id] | length' "$LANE_DIR/signals.json")
[ "$INVALID_RULES" = "0" ] || die "E145" "Invalid rule_id format: $INVALID_RULES"

# VND_DECIMAL_PRESENT severity check (must be HIGH)
VND_LOW_SEVERITY=$(jq -r '[.signals[] | select(.kind == "VND_DECIMAL_PRESENT" and .severity != "HIGH" and .severity != "MUST")] | length' "$LANE_DIR/signals.json")
[ "$VND_LOW_SEVERITY" = "0" ] || die "E145" "VND_DECIMAL_PRESENT signals phải severity HIGH/MUST (compliance gate). Found $VND_LOW_SEVERITY violations."

# T4 — File resolution (WARN only)
UNRESOLVED=$(jq -r --slurpfile g "$FE_COMP_GRAPH" \
  '[.signals[] | .affected_files[]?] | unique
   | map(select(. as $f | ($g[0].nodes | map(.file_path) | index($f)) == null))
   | length' "$LANE_DIR/signals.json")
[ "$UNRESOLVED" = "0" ] || log_warn "E045" "Unresolved files count: $UNRESOLVED"
```
