## §A Header

Lane CD15 đảm bảo **UI permission gates mirror BE authorization rules** — zero trust UI + RBAC catalog consistency. Phát hiện UI gates dùng permission key không tồn tại RBAC, BE auth không có UI gate (user thấy menu nhưng click → 403), naming drift, admin actions thiếu permission guard.

**Vì sao quan trọng:**
- Security gap: admin UI action không guard → privilege escalation
- UX bug: BE auth không UI mirror → user thấy nút nhưng click 403 → confusion
- Naming drift `crm-customer-read` vs `crm.customer.read` → policy enforcement không match → silent bypass

**Reference design canon:** `docs/04-skill-design/wf-cmi/agent-prompt.md §21`

**Shared sections cần load:**
- `procedures/_shared.md §1, §3, §6 Atomic Write, §12 CI Detection`

## §C Steps

### Step CD15.1 — Load 2 graphs + SSOT into agent context

```bash
FE_PERM_NODES=$(jq -c '.nodes' "$FE_PERM")

log_phase_event "phase4_cd15" "INFO" \
  "{\"fe_perm_nodes\":$FE_PERM_COUNT,\"be_endpoints\":$(jq '.endpoints // .nodes | length' "$BE_API"),\"rbac_perms\":$PERM_COUNT,\"roles\":$ROLE_COUNT}"
```

### Step CD15.2 — Orphan UI permission (ORPHAN_UI_PERMISSION)

> FE permission key không tồn tại trong RBAC catalog.

**Logic:**
1. Iterate `fe-permission-graph.nodes[]` filter `permission_key != null AND permission_key != "dynamic_or_variable"`
2. Cross-ref RBAC catalog: lookup permission_key trong `RBAC_PERM_KEYS`
3. Không tìm thấy → ORPHAN_UI_PERMISSION (severity SHOULD)
4. Skip permissions trong `exclusions[]` của RBAC catalog (public endpoints)

**Signal payload:**
```json
{
  "kind": "ORPHAN_UI_PERMISSION",
  "severity": "SHOULD",
  "category": "VIOLATION",
  "rule_id": "UIPM-CD15-001",
  "message": "FE component CustomerDeleteButton dùng permission crm.customer.delete_force nhưng không tồn tại trong RBAC catalog",
  "affected_entities": ["crm.customer.delete_force"],
  "affected_files": ["apps/erp-web/components/customer-delete-button.tsx"],
  "evidence": [{"file": "apps/erp-web/components/customer-delete-button.tsx", "line": 8, "snippet": "<PermissionGate permission=\"crm.customer.delete_force\">"}],
  "suggested_action": "Verify typo (crm.customer.delete?) hoặc add new permission vào rbac-permission-catalog.json"
}
```

### Step CD15.3 — BE auth without UI gate (BE_AUTH_NO_UI_GATE)

> BE endpoint có `[Authorize(Policy="X")]` nhưng FE không có PermissionGate cho permission X.

**Logic:**
1. Iterate `api-graph.endpoints[]` filter `requires_auth=true` AND `policy != null`
2. Build set FE permission keys từ `fe-permission-graph.nodes[].permission_key`
3. Endpoint policy không trong FE set → BE_AUTH_NO_UI_GATE (severity SHOULD)
4. Mitigation: chỉ flag endpoints user-facing (controller có pattern `/api/v1/{module}/...` — exclude `/api/internal/...`)

**Rule ID:** `UIPM-CD15-002`

**Note:** UI gate có thể ở route level (middleware) không component level — kiểm tra cả `fe-route-graph.json.middleware[]` nếu graph có (v2.1).

### Step CD15.4 — Dynamic permission unverifiable (DYNAMIC_PERMISSION_UNVERIFIABLE)

> FE nodes có `permission_key="dynamic_or_variable"` — không static-verify được.

**Logic:**
1. Iterate FE nodes filter `permission_key="dynamic_or_variable"`
2. Build signal per node với severity MAY (informational)
3. Suggested action: refactor thành const string hoặc lookup table

**Rule ID:** `UIPM-CD15-003`

**Note:** Severity MAY vì có thể intentional (vd role-based dynamic). Output category=RECOMMENDATION để Phase 7 triage không hard-block.

### Step CD15.5 — Permission naming drift (PERMISSION_NAMING_DRIFT)

> Permission key convention: `{module}.{entity}.{action}` (vd `crm.customer.read`).

**Logic:**
1. Iterate FE nodes filter `permission_key != null AND != "dynamic_or_variable"`
2. Check naming convention regex: `^[a-z][a-z0-9]*(\.[a-z][a-z0-9_]*){2,3}$`
   - Vi phạm patterns: `CRM_CUSTOMER_READ` (snake upper), `crm-customer-read` (kebab), `crm.Customer.Read` (mixed case)
3. → PERMISSION_NAMING_DRIFT (severity SHOULD)
4. Cross-validate với RBAC catalog config:
   - Nếu `config.naming_convention="lowercase_dot"` AND FE dùng khác → flag

**Rule ID:** `UIPM-CD15-004`

### Step CD15.6 — Missing permission for admin action (MISSING_PERMISSION_FOR_ADMIN_ACTION)

> UI action high-risk (delete/bulk-delete/system-config) không có permission guard.

**Logic:**
1. Iterate `fe-permission-graph.nodes[]` — nhưng cũng cần check components KHÔNG có permission guard
2. Cross-ref với `fe-component-graph.json.nodes[]` (nếu lane CD11 đã build hoặc graph có sẵn):
   - Component file_path match patterns: `admin/`, `system/`, `settings/`, hoặc component name match `Delete|BulkDelete|Reset|Purge|Admin`
   - Component KHÔNG có corresponding FE permission node ở same file
3. → MISSING_PERMISSION_FOR_ADMIN_ACTION (severity MUST — security risk)

**Rule ID:** `UIPM-CD15-005`

**Limitation v1.0:** Heuristic match path/name — false positive nếu component admin ở module CRM (vd `apps/erp-web/components/crm/customer-admin-tools.tsx`). v2.1 cross-ref permissions ở parent layout.

### Step CD15.7 — Write signals.json (Atomic Write)

```bash
SIGNALS_TMP="$LANE_DIR/.signals.tmp.$$"

jq -n \
  --arg sid "$SESSION_ID" \
  --arg ts "$(date -Iseconds)" \
  --arg lane "CD15" \
  --arg agent "frontend-developer" \
  --arg scope_type "$SCOPE_TYPE" \
  --argjson signals "$ALL_SIGNALS_JSON" \
  --argjson modules_covered "$MODULES_COVERED" \
  --arg ci "$CI_SOURCE" \
  '{
    "$schema": "signals-v1",
    "session_id": $sid,
    "generated_at": $ts,
    "lane": $lane,
    "agent_subagent_type": $agent,
    "scope": {"type": $scope_type, "modules": $modules_covered},
    "status": "COMPLETED",
    "scan_duration_sec": ($scan_duration | tonumber),
    "signals": $signals,
    "metadata": {
      "signal_count": ($signals | length),
      "severity_breakdown": {
        "MUST": ([$signals[] | select(.severity == "MUST")] | length),
        "SHOULD": ([$signals[] | select(.severity == "SHOULD")] | length),
        "MAY": ([$signals[] | select(.severity == "MAY")] | length),
        "INFO": ([$signals[] | select(.severity == "INFO")] | length)
      },
      "category_breakdown": {
        "MISSING_INVARIANT": ([$signals[] | select(.category == "MISSING_INVARIANT")] | length),
        "VIOLATION": ([$signals[] | select(.category == "VIOLATION")] | length),
        "GAP": ([$signals[] | select(.category == "GAP")] | length),
        "RECOMMENDATION": ([$signals[] | select(.category == "RECOMMENDATION")] | length)
      },
      "modules_covered": $modules_covered,
      "ci_source": $ci,
      "fallback_used": false
    }
  }' > "$SIGNALS_TMP"

jq '.' "$SIGNALS_TMP" >/dev/null || die "E044" "signals.json invalid JSON"
mv "$SIGNALS_TMP" "$LANE_DIR/signals.json"
```

### Step CD15.8 — Write CD15 report (CORE-028, ≤15 dòng tiếng Việt)

```bash

**Kết quả:** $N_SIGNALS signals — MUST: $N_MUST (security risk), SHOULD: $N_SHOULD, MAY: $N_MAY, INFO: $N_INFO. Coverage cấp lane: ${LANE_COVERAGE_PCT}%. File đầu ra: signals.json + lane-status.json.
```

## §D POST-GATE (T1→T4 + Auto-Fix)

| Tier | Check | Tool | Fail action |
|------|-------|------|-------------|
| T1 | 3 output files exist | bash | **E044** — Output missing → auto-fix retry x3 |
| T2 | `signals.json` schema = `signals-v1`, `lane` = "CD15", fingerprint unique | jq | **E044** — Schema invalid → re-build |
| T3 | Mọi signal `rule_id` match format `UIPM-CD15-\d{3}` (001-005) AND tồn tại trong RBAC `validation_rules[].id` (nếu rule_id cần SSOT mapping) | jq | **E144** — Rule_id orphan → ESCALATE (signal false positive hoặc SSOT thiếu rule) |
| T4 | `affected_entities[]` permission keys resolve trong `rbac-permission-catalog.permissions[].key` HOẶC mark as orphan signal | jq | **E045** — Permission unresolved → log WARN |

```bash
# T1
for f in signals.json CD15-ui-permission-mirror-report.md lane-status.json; do
  [ -f "$LANE_DIR/$f" ] || die "E044" "Output missing: $f"
done

# T2
SCHEMA=$(jq -r '."$schema"' "$LANE_DIR/signals.json")
LANE_VAL=$(jq -r '.lane' "$LANE_DIR/signals.json")
[ "$SCHEMA" = "signals-v1" ] || die "E044" "Schema mismatch"
[ "$LANE_VAL" = "CD15" ] || die "E044" "Lane field mismatch"

FP_TOTAL=$(jq '.signals | length' "$LANE_DIR/signals.json")
FP_UNIQUE=$(jq '[.signals[].fingerprint] | unique | length' "$LANE_DIR/signals.json")
[ "$FP_TOTAL" = "$FP_UNIQUE" ] || die "E044" "Fingerprint collision"

# T3 — Rule ID format + SSOT mapping
INVALID_RULES=$(jq -r '[.signals[] | select(.rule_id | test("^UIPM-CD15-[0-9]{3}$") | not) | .rule_id] | length' "$LANE_DIR/signals.json")
[ "$INVALID_RULES" = "0" ] || die "E144" "Invalid rule_id format: $INVALID_RULES"

ORPHAN_RULES=$(jq -r --slurpfile ssot "$SSOT_RBAC" \
  '[.signals[].rule_id] - ($ssot[0].validation_rules | map(.id)) | length' \
  "$LANE_DIR/signals.json")
[ "$ORPHAN_RULES" = "0" ] || log_warn "E144" "Orphan rule_id count: $ORPHAN_RULES (rules thiếu trong SSOT validation_rules)"

# T4 — Permission resolution (WARN only — ORPHAN_UI_PERMISSION signals intentionally have unresolved permissions)
UNRESOLVED=$(jq -r --slurpfile ssot "$SSOT_RBAC" \
  '[.signals[] | select(.kind != "ORPHAN_UI_PERMISSION") | .affected_entities[]?] | unique
   | map(select(. as $p | ($ssot[0].permissions | map(.key) | index($p)) == null))
   | length' "$LANE_DIR/signals.json")
[ "$UNRESOLVED" = "0" ] || log_warn "E045" "Unresolved permissions count: $UNRESOLVED (ngoài RBAC catalog scope)"
```

**Auto-fix budget (CORE-034):** Max 3 retries. Hết → ESCALATE FAIL.
