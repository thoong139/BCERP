## §A Header

Lane CD26 đảm bảo **visibility của workflow states + actor roles** trong UI cho mọi entity có state machine. Logistics-aware: Booking (8 states) / CustomsDeclaration (6 states) / Invoice (5 states, TT 78/2021 lifecycle) PHẢI có status badge + timeline + transition history visible cho user.

**Vì sao logistics-critical (★★★):**
- Booking state ẩn → operator không biết phải approve hay submit → workflow stuck
- Customs declaration state UI thiếu → user không biết khai báo đã được approve/rejected → re-submit duplicate
- Invoice lifecycle (draft→issued→paid) không visible → finance team confused về AR aging
- Transition history thiếu → compliance audit fail (CD29 dependency) — cần trace ai approve khi nào
- Actor role ambiguous → 2 user cùng claim ownership → duplicate work hoặc bỏ sót


### Step CD26.2 — Workflow state unclear UI (WORKFLOW_STATE_UNCLEAR_UI)

> Entity có state machine nhưng UI list/detail không hiển thị status.

**Logic:**
1. Iterate `SM_ENTITY_LIST` — mỗi entry có `entity` + `name` + `states[]`
2. For each entity, find corresponding routes:
   - List page: `fe-route-graph.nodes[]` filter `route_path` regex `^/(?:[a-z-]+/)*${entity-plural}/?$` (vd `/crm/customers`, `/bookings`)
   - Detail page: regex `^/(?:[a-z-]+/)*${entity-plural}/\[id\](?:/.*)?$` (vd `/crm/customers/[id]`)
3. For each found page, scan file_path component cho status display:
   - Grep `<StatusBadge|<StatusChip|<state-badge|<StatusIndicator|status:|<Badge.*status`
   - Cross-ref columns array (cho list page): `columns:.*status|dataIndex.*status|accessorKey.*status`
4. Page list KHÔNG có StatusBadge column → WORKFLOW_STATE_UNCLEAR_UI (severity **HIGH**)
5. Page detail KHÔNG có status display → WORKFLOW_STATE_UNCLEAR_UI (severity HIGH)
6. Cross-validate với `ux_visibility_requirements.requirements[].id="UX-VIS-001"`

**Signal payload:**
```json
{
  "kind": "WORKFLOW_STATE_UNCLEAR_UI",
  "severity": "HIGH",
  "category": "VIOLATION",
  "rule_id": "UXWFV-CD26-001",
  "message": "Entity Booking (state machine: 8 states) — list page /bookings không có StatusBadge column",
  "affected_entities": ["Booking"],
  "affected_files": ["apps/erp-web/app/(authenticated)/bookings/page.tsx"],
  "evidence": [{"file": "apps/erp-web/app/(authenticated)/bookings/page.tsx", "expected_states": ["draft","submitted","approved","in_transit","delivered","completed","cancelled","rejected"], "status_column_present": false}],
  "suggested_action": "Add StatusBadge column: { title: 'Trạng thái', dataIndex: 'status', render: (s) => <StatusBadge state={s} machine='Booking' /> }"
}
```

### Step CD26.3 — Missing status indicator (MISSING_STATUS_INDICATOR)

> Action button không show current state context — user không biết action có khả dụng không.

**Logic:**
1. Iterate `SM_ENTITY_LIST` — extract `transitions[]` (mỗi entry: `{from, to, action}`)
2. For each entity, find detail/action components qua `fe-component-graph.nodes[]` filter related to entity
3. Grep action handlers patterns:
   - `onApprove\s*=` / `handleApprove\s*=`
   - `onReject\s*=` / `handleReject\s*=`
   - `onConfirm\s*=` / `onCancel\s*=`
   - `onSubmit\s*=` / `onComplete\s*=`
4. For each action button found, check same file/scope cho status display near button:
   - `<StatusBadge|<CurrentState|state:|currentStatus:` within 50 lines context
5. Action button KHÔNG có nearby state display → MISSING_STATUS_INDICATOR (severity SHOULD)
6. Cross-ref transitions: action chỉ valid từ certain states → ideally show conditional rendering

**Rule ID:** `UXWFV-CD26-002`

### Step CD26.4 — Actor role ambiguous (ACTOR_ROLE_AMBIGUOUS)

> Detail page không show owner/assigned actor — multi-user confusion.

**Logic:**
1. Iterate `SM_ENTITY_LIST` — focus entities có `owner_module` declared
2. Cross-ref `be-domain-graph.json.nodes[]` filter `kind=aggregate_root` name=entity:
   - Check entity có ownership properties: `owner_id|assignedTo|responsibleUser|createdBy`
3. For each entity, find detail page (route + component)
4. Grep file_path components patterns:
   - `<Owner|<AssignedTo|<Assignee|<UserBadge|<ResponsibleUser`
   - `owner_id|owner_name|assignee|assigned_to|responsible_user|created_by_user` data binding
5. Detail page KHÔNG show actor display → ACTOR_ROLE_AMBIGUOUS (severity SHOULD)
6. Skip entities trong `WSM_EXCLUSIONS` (reference data không có owner concept)

**Rule ID:** `UXWFV-CD26-003`

### Step CD26.5 — Progress hidden (PROGRESS_HIDDEN)

> Multi-step workflow (states ≥5) không có Timeline/Stepper visualization.

**Logic:**
1. Iterate `SM_ENTITY_LIST` filter `states_count >= 5` (multi-step workflows)
2. For each entity, find detail page
3. Grep file_path patterns:
   - `<Stepper|<Steps|<Timeline|<WorkflowSteps|<ProgressSteps`
   - `<Progress.*current|currentStep:`
   - `<TransitionGraph|<StateGraph`
4. Detail page KHÔNG có progress component → PROGRESS_HIDDEN (severity SHOULD)
5. **Logistics-critical override:** Booking (8 states), CustomsDeclaration (6 states), Invoice (5 states) — severity **HIGH** (logistics ★★★)
6. Cross-validate với `ux_visibility_requirements.requirements[].ui_pattern` cho timeline patterns

**Rule ID:** `UXWFV-CD26-004`

### Step CD26.6 — Missing transition history (MISSING_TRANSITION_HISTORY)

> Workflow ≥3 events_published không có history component → audit trail gap.

**Logic:**
1. Iterate `SM_ENTITY_LIST` filter `events_published[].length >= 3` (significant state machines)
2. For each entity, find detail page
3. Grep patterns:
   - `<History|<AuditLog|<TransitionLog|<EventTimeline|<StateHistory|<ActivityLog`
   - `state_history|transition_history|audit_log:` data bindings
   - `<Timeline.*events:` (timeline showing events)
4. Detail page KHÔNG có history component → MISSING_TRANSITION_HISTORY (severity SHOULD)
5. **Compliance-critical override:** Entities trong `audit-critical-entities.json` (CD29 SSOT — nếu tồn tại) → severity HIGH
6. Cross-validate với CD29 lane signals nếu cùng session (cross-lane signal)

**Rule ID:** `UXWFV-CD26-005`

### Step CD26.7 — Write signals.json (Atomic Write)

```bash
SIGNALS_TMP="$LANE_DIR/.signals.tmp.$$"

jq -n \
  --arg sid "$SESSION_ID" \
  --arg ts "$(date -Iseconds)" \
  --arg lane "CD26" \
  --arg agent "ux-designer" \
  --arg scope_type "$SCOPE_TYPE" \
  --argjson signals "$ALL_SIGNALS_JSON" \
  --argjson modules_covered "$MODULES_COVERED" \
  --argjson sm_list "$SM_ENTITY_LIST" \
  --arg ci "$CI_SOURCE" \
  '{
    "$schema": "signals-v1",
    "session_id": $sid,
    "generated_at": $ts,
    "lane": $lane,
    "agent_subagent_type": $agent,
    "scope": {"type": $scope_type, "modules": $modules_covered},
    "status": "COMPLETED",
    "scan_duration_sec": ($scan_duration | tonumber),
    "signals": $signals,
    "metadata": {
      "signal_count": ($signals | length),
      "severity_breakdown": {
        "MUST": ([$signals[] | select(.severity == "MUST")] | length),
        "HIGH": ([$signals[] | select(.severity == "HIGH")] | length),
        "SHOULD": ([$signals[] | select(.severity == "SHOULD")] | length),
        "MAY": ([$signals[] | select(.severity == "MAY")] | length),
        "INFO": ([$signals[] | select(.severity == "INFO")] | length)
      },
      "category_breakdown": {
        "MISSING_INVARIANT": ([$signals[] | select(.category == "MISSING_INVARIANT")] | length),
        "VIOLATION": ([$signals[] | select(.category == "VIOLATION")] | length),
        "GAP": ([$signals[] | select(.category == "GAP")] | length),
        "RECOMMENDATION": ([$signals[] | select(.category == "RECOMMENDATION")] | length)
      },
      "modules_covered": $modules_covered,
      "ci_source": $ci,
      "fallback_used": false,
      "state_machines_audited": ($sm_list | length),
      "logistics_critical_signals": {
        "PROGRESS_HIDDEN_BOOKING_CUSTOMS_INVOICE": ([$signals[] | select(.kind == "PROGRESS_HIDDEN" and (.affected_entities[] | IN("Booking","CustomsDeclaration","Invoice")))] | length)
      }
    }
  }' > "$SIGNALS_TMP"

jq '.' "$SIGNALS_TMP" >/dev/null || die "E044" "signals.json invalid JSON"
mv "$SIGNALS_TMP" "$LANE_DIR/signals.json"
```

```bash
for f in signals.json CD26-ux-workflow-visibility-report.md lane-status.json; do
```
