## §A Header

Lane CD31 đảm bảo **hai khía cạnh money + tax** trong ERP logistics đa tiền tệ:

**(A) Money Integrity** — Mọi money field:
- Decimal precision đúng currency rule (VND scale=0, CNY/USD scale=2, gold scale=4)
- KHÔNG dùng float/double (IEEE 754 sai số)
- Money value object (Amount + Currency) thay vì raw decimal
- Currency-aware operations (KHÔNG add/subtract giữa 2 currencies thiếu FX conversion)

**(B) Tax Integrity** — Mọi tax calculation:
- Tuân thủ tax rates effective date (VAT VN 8%/10% theo NQ 142/2024/QH15, VAT CN 13%/9%/6%)
- Rounding rules (TT 80/2021/TT-BTC HALF_UP cho VN)
- Tax breakdown đầy đủ (subtotal + tax = total per line item)
- FX rate source traceability (SBV/PBoC API, KHÔNG hardcoded)

**Vì sao logistics-critical (★★★):**
- Tax rate hết hạn → vi phạm regulatory → phạt + truy thu thuế
- Float money → sai số tích lũy → mismatch sổ sách
- Currency mismatch trong calculation → lệch công nợ cross-border VN-CN-international
- FX hardcoded → lệch trị giá hải quan + invoice export
- Customs valuation theo Incoterms (FOB/CIF/EXW) + freight + insurance

### Step CD31.2 — Decimal precision check (WRONG_DECIMAL_SCALE, CRITICAL_FLOAT_MONEY)

> Mỗi money column trong DB phải có scale đúng currency rule.

**Logic:**
1. Iterate `be-db-schema-graph.json.columns[]` filter `sql_type LIKE 'numeric%' OR 'decimal' OR 'money'`:
   - Heuristic detect money column: tên column matching `*Amount*|*Price*|*Cost*|*Total*|*Fee*|*Tax*|*Subtotal*|*Discount*|*Balance*`
2. Cross-ref `reference_data.currencies[]` từ SSOT MDM:
   - Mỗi currency có `scale` (vd VND=0, USD=2, CNY=2, gold/silver=4)
   - Resolve column → currency qua entity property (kiểm tra entity có `CurrencyCode` field hoặc Money VO chứa Currency)
3. Compare scale:
   - DB scale ≠ currency.scale → WRONG_DECIMAL_SCALE (severity MUST — silent rounding loss)
   - vd VND column scale=2 thay vì 0 → loss 0.99 VND mỗi row
4. Iterate columns filter `sql_type IN ('real', 'double precision', 'float')`:
   - Tên matching money pattern → CRITICAL_FLOAT_MONEY (severity **CRITICAL** — IEEE 754 không exact, luôn fail tax audit)

**Rule IDs:** `MONEY-CD31-001` (wrong scale) | `MONEY-CD31-002` (float money)

**Signal payload:**
```json
{
  "kind": "CRITICAL_FLOAT_MONEY",
  "severity": "MUST",
  "category": "VIOLATION",
  "rule_id": "MONEY-CD31-002",
  "message": "Column Invoices.TotalAmount dùng double precision — phải numeric(18,2) cho USD/CNY hoặc numeric(18,0) cho VND. IEEE 754 sai số tích lũy = fail tax audit.",
  "affected_columns": ["Invoices.TotalAmount"],
  "affected_files": ["apps/backend/Eureka.Modules.Finance/Domain/Invoice.cs"],
  "evidence": [{"file": "...", "line": 25, "snippet": "public double TotalAmount { get; set; }"}],
  "suggested_action": "Đổi sang decimal Money VO: public Money TotalAmount { get; private set; } với Money(decimal amount, Currency currency). DB column numeric(18, <scale>) per currency rule."
}
```

### Step CD31.3 — Money value object usage (MISSING_MONEY_VALUE_OBJECT, INCOMPLETE_MONEY_TYPE)

> Money fields phải dùng custom Money VO (Amount + Currency), không raw decimal.

**Logic:**
1. Iterate `be-domain-graph.json` properties filter type=`decimal` AND name matching money pattern:
   - Loại trừ properties trong VO `Money` (`be-domain-graph.json` kind=value_object name=Money)
   - Còn lại → MISSING_MONEY_VALUE_OBJECT (severity SHOULD — mất currency context)
2. Iterate `be-domain-graph.json` filter `kind=value_object AND name=Money`:
   - Money VO phải có ≥2 properties: `Amount` (decimal) + `Currency` (Currency type hoặc string CurrencyCode)
   - Thiếu Currency field → INCOMPLETE_MONEY_TYPE (severity MUST — mất currency = silent bug)
3. Iterate `kind=value_object` khác với pattern name `*Money*|*Price*|*Cost*`:
   - Apply same check (Amount + Currency required)

**Rule IDs:** `MONEY-CD31-003` (missing VO) | `MONEY-CD31-004` (incomplete VO)

### Step CD31.4 — Currency mismatch in calculation (CURRENCY_MISMATCH_RISK, MIXED_CURRENCY_HEADER)

> Operations Add/Subtract money giữa 2 currencies khác nhau phải qua FX conversion.

**Logic:**
1. Iterate `be-cqrs-graph.json.command_handlers[]` + `query_handlers[]`:
   - Grep handler body cho patterns `+ Money|.Add(|.Subtract(|.Plus(|.Minus(` (CI: Serena `find_symbol` Money class + operators)
   - Resolve operand currencies — nếu 2 operands từ entities khác currency context (vd Invoice.Currency=VND + Fee.Currency=USD) → CURRENCY_MISMATCH_RISK (severity MUST — kết quả sai)
2. Iterate Invoice/Order/Quotation aggregates:
   - Header có `Currency` field
   - Line items có `Money` VO với Currency
   - Nếu line item Currency ≠ header Currency mà KHÔNG có conversion → MIXED_CURRENCY_HEADER (severity SHOULD)
3. Loại trừ patterns đã có explicit `.ConvertTo(Currency)` hoặc `.ToCurrency(Currency, rate)`

**Rule IDs:** `MONEY-CD31-005` (mismatch risk) | `MONEY-CD31-006` (mixed header)

**Note:** Lane KHÔNG runtime evaluate — chỉ static. Edge cases dynamic currency → log INFO suggest manual review.

### Step CD31.5 — Tax rate compliance (EXPIRED_TAX_RATE, MISSING_ROUNDING_RULE)

> Tax rates hardcoded phải khớp regulation effective date.

**Logic:**
1. Grep code patterns cho hardcoded tax rates:
   - `Grep "0\.10|0\.08|0\.13|0\.09|0\.06|VatRate|TaxRate"` (regex match thường gặp)
   - Extract value + context (file + line)
2. Cross-ref `compliance-mapping.json.tax_regulations[]`:
   - Mỗi entry: `{country, tax_type, rate, effective_from, effective_until, regulation_ref}` (vd `{country:"VN", tax_type:"VAT_STANDARD", rate:0.10, effective_from:"2024-07-01", effective_until:null, regulation_ref:"NQ 142/2024/QH15"}`)
   - Match hardcoded rate vs regulation rate active today
   - Hardcoded rate match expired regulation (`effective_until < TODAY`) → EXPIRED_TAX_RATE (severity **MUST CRITICAL** — đang vi phạm compliance)
   - Hardcoded rate KHÔNG match bất kỳ active regulation → MAY (log INFO suggest review — có thể là rate đặc biệt hợp lệ)
3. Iterate tax calculation methods (Grep `CalculateTax|ApplyVat|ComputeTax`):
   - Check có declare rounding rule (vd `MidpointRounding.AwayFromZero` cho VN HALF_UP per TT 80/2021)
   - Thiếu rounding declaration → MISSING_ROUNDING_RULE (severity SHOULD)

**Rule IDs:** `TAX-CD31-007` (expired) | `TAX-CD31-008` (missing rounding)

### Step CD31.6 — Tax breakdown completeness (INCOMPLETE_TAX_BREAKDOWN)

> Mỗi Invoice/Order line item phải có tax_code + tax_rate + tax_base + tax_amount.

**Logic:**
1. Find aggregates kind=`aggregate_root` name matching `Invoice|Order|Quotation|TaxInvoice`:
   - Line items (child entity hoặc value object collection)
2. Check line item properties:
   - Required: `TaxCode|TaxType` (string ref to tax_regulations[].id), `TaxRate` (decimal), `TaxBase|SubtotalBeforeTax` (Money), `TaxAmount` (Money)
   - Thiếu bất kỳ field nào → INCOMPLETE_TAX_BREAKDOWN (severity MUST — fail tax audit per Thông tư 78/2021)
3. Domain invariant check: `subtotal + tax_amount = total` — verify trong aggregate validate method (Grep `Validate(|.Validate(|Check(`)
   - Không thấy invariant code → INCOMPLETE_TAX_BREAKDOWN với evidence "missing total invariant"

**Rule ID:** `TAX-CD31-009`

### Step CD31.7 — FX rate source traceability (MISSING_FX_AUDIT_TRAIL, HARDCODED_FX_RATE)

> FX conversion phải lưu rate + source + timestamp.

**Logic:**
1. Grep code patterns:
   - `Grep "ExchangeRate|FxRate|ConvertCurrency|ExchangeRateProvider"`
2. Per match, check có lưu audit trail:
   - Required fields: `rate_value` + `rate_source` (vd "SBV", "PBoC", "ECB") + `rate_date` + `from_currency` + `to_currency`
   - Thiếu rate_source hoặc rate_date → MISSING_FX_AUDIT_TRAIL (severity MUST — gold accounting requirement)
3. Detect hardcoded FX rates:
   - Pattern: `var rate = 24500m|var rate = 7\.20m` hoặc constants `const decimal VND_USD_RATE = 24500`
   - HARDCODED_FX_RATE (severity **MUST CRITICAL** — phải gọi API hoặc store rate history table)
4. Test fixtures excluded (path `**/Tests/**`, `**/*Test*.cs`, `**/SeedData/dev/**`)

**Rule IDs:** `TAX-CD31-010` (missing audit trail) | `TAX-CD31-011` (hardcoded FX)

```bash
# T1
for f in signals.json CD31-money-tax-integrity-report.md lane-status.json; do
  [ -f "$LANE_DIR/$f" ] || die "E044" "Output missing: $f"
done

# T2
SCHEMA=$(jq -r '."$schema"' "$LANE_DIR/signals.json")
LANE_VAL=$(jq -r '.lane' "$LANE_DIR/signals.json")
[ "$SCHEMA" = "signals-v1" ] || die "E044" "Schema mismatch: $SCHEMA"
[ "$LANE_VAL" = "CD31" ] || die "E044" "Lane field mismatch: $LANE_VAL"

FP_TOTAL=$(jq '.signals | length' "$LANE_DIR/signals.json")
FP_UNIQUE=$(jq '[.signals[].fingerprint] | unique | length' "$LANE_DIR/signals.json")
[ "$FP_TOTAL" = "$FP_UNIQUE" ] || die "E044" "Fingerprint collision: total=$FP_TOTAL unique=$FP_UNIQUE"

# T3 — Rule ID format
INVALID_RULES=$(jq -r \
  '[.signals[] | select(.rule_id | test("^(MONEY|TAX)-CD31-[0-9]{3}$") | not) | .rule_id] | length' \
  "$LANE_DIR/signals.json")
[ "$INVALID_RULES" = "0" ] || die "E143" "Invalid rule_id format count: $INVALID_RULES (must match MONEY-CD31-NNN or TAX-CD31-NNN)"

# Rule ID resolution — check 1 trong 2 SSOTs có rule
ORPHAN_RULES=$(jq -r --slurpfile mdm "$SSOT_MDM" --slurpfile comp "$SSOT_COMPLIANCE" \
  '[.signals[].rule_id] -
   (($mdm[0].validation_rules // []) + ($comp[0].validation_rules // []) | map(.id)) | length' \
  "$LANE_DIR/signals.json")
[ "$ORPHAN_RULES" = "0" ] || log_warn "E143" "Orphan rule_id count: $ORPHAN_RULES"

# T4 — Tax rate cross-validation (WARN only)
TAX_UNRESOLVED=$(jq -r --slurpfile comp "$SSOT_COMPLIANCE" --arg today "$TODAY" \
  '[.signals[] | select(.kind == "EXPIRED_TAX_RATE" or .kind == "MISSING_ROUNDING_RULE")
    | select(.regulation_ref as $r |
       ($comp[0].tax_regulations // []) | map(.regulation_ref) | index($r) == null)
    | .rule_id] | length' \
  "$LANE_DIR/signals.json" 2>/dev/null || echo "0")
[ "$TAX_UNRESOLVED" = "0" ] || log_warn "E045" "Tax rate signals unresolved against regulations: $TAX_UNRESOLVED"
```
