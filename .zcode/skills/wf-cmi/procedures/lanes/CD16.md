## §A Header

Lane CD16 đảm bảo **tính toàn vẹn logic miền (Domain Logic Integrity)** trong codebase backend DDD .NET — aggregate boundary integrity, domain event completeness, value object immutability, business behavior richness. Sub-stage 4.2 BE deep lane phức tạp do cần hiểu DDD invariants từ pattern phân tích graph thay vì code thật.

**Vì sao quan trọng:**
- Aggregate boundary violation → bypass aggregate consistency rule → silent data corruption khi 2 aggregates compete write
- Domain event missing → bounded contexts khác (subscribers) không biết state change → eventual consistency broken
- Value object leak → shared mutable reference → unpredictable side effects khi caller modify VO của entity khác
- Anemic domain model → business logic scattered across services → code rot + duplicate logic + race conditions

### Step CD16.2 — Aggregate boundary violation (AGGREGATE_BOUNDARY_VIOLATION)

> Aggregate A có direct reference tới Entity X của aggregate B khác → vi phạm DDD rule "aggregates reference each other by ID only".

**Logic:**
1. Build set `aggregate_owners{}` — map entity name → owning aggregate (entity thuộc cùng module với aggregate gần nhất)
   - Heuristic v1.0: entity ở `Eureka.Modules.{X}.Domain.{Aggregate}/` thuộc aggregate `{Aggregate}` trong module X
2. Iterate `edges[]` filter `kind=references_entity` HOẶC `kind=aggregates`:
   - For each edge `{from: aggregateA, to: entityX}`:
     - Resolve aggregate owning entityX qua `aggregate_owners[entityX]`
     - Nếu owner ≠ aggregateA AND entityX KHÔNG phải value_object → AGGREGATE_BOUNDARY_VIOLATION (severity MUST)
3. Loại trừ:
   - Reference through interface/value_object (vd `Customer.Address` là VO, không vi phạm)
   - Reference qua FK ID property (vd `Order.CustomerId: Guid` không phải reference entity instance)
   - Aggregate trong module Shared/Common (vd `Eureka.Shared.Domain.AuditableEntity` → skip)

**Signal payload:**
```json
{
  "kind": "AGGREGATE_BOUNDARY_VIOLATION",
  "severity": "MUST",
  "category": "VIOLATION",
  "rule_id": "DDD-CD16-001",
  "message": "Aggregate Order (module Sales) reference trực tiếp Entity Customer (module CRM) — vi phạm aggregate boundary",
  "affected_entities": ["Order", "Customer"],
  "affected_files": ["apps/backend/Eureka.Modules.Sales/Domain/Orders/Order.cs"],
  "evidence": [
    {"file": "apps/backend/Eureka.Modules.Sales/Domain/Orders/Order.cs", "line": 28, "snippet": "public Customer Customer { get; private set; }"}
  ],
  "suggested_action": "Thay reference Customer instance bằng CustomerId: Guid + truy vấn Customer qua repository khi cần. Hoặc tạo CustomerSnapshot value-object snapshot tại thời điểm Order tạo."
}
```

### Step CD16.3 — Domain event missing (DOMAIN_EVENT_MISSING)

> Aggregate state-changing method nhưng KHÔNG raise domain event → bounded contexts khác không biết state change.

**Logic:**
1. Iterate aggregates với HAS_CQRS_GRAPH=true:
   - Cross-ref `be-cqrs-graph.json.nodes[]` filter `kind=request_handler`
   - Filter handlers có edge `kind=handles` tới Command có name pattern matching aggregate (vd `UpdateCustomerCommand` targets aggregate `Customer`)
2. For each (aggregate, handler) pair:
   - Check `be-domain-graph.json.edges[]` filter `kind=raises_event` từ aggregate
   - Nếu handler edit aggregate state (heuristic: command name có verb `Update|Create|Delete|Approve|Cancel|Confirm|Complete|Reject|Submit`) NHƯNG aggregate KHÔNG có raises_event edge → DOMAIN_EVENT_MISSING (severity SHOULD)
3. Skip:
   - Aggregates marked `is_event_sourced=false` trong metadata
   - Read-only aggregates (chỉ có Query handlers, không có Command)
   - Aggregates trong module Read/Projection (CQRS read-side)

**Rule ID:** `DDD-CD16-002`

**Note:** Nếu HAS_CQRS_GRAPH=false → skip step này, log WARN E133 "DOMAIN_EVENT_MISSING coverage downgrade — be-cqrs-graph required". KHÔNG fail lane.

### Step CD16.4 — Value object leak (VALUE_OBJECT_LEAK)

> Value object phải immutable — không public setter, không method modify state in-place.

**Logic:**
1. Iterate `nodes[]` filter `kind=value_object`:
   - Heuristic v1.0 từ `properties_count` + name pattern — KHÔNG đọc lại file
   - Cross-ref edges từ aggregate `kind=uses_value_object` → check VO có method "Set*", "Update*", "Change*" trong base_types nếu graph metadata có
2. v1.0 limitation: graph parser chỉ track properties_count, không track setter visibility. Lane CD16 dùng heuristic:
   - VO có `properties_count > 0` AND chứa pattern method trong `base_types[]` matching `^(Set|Update|Change)` → VALUE_OBJECT_LEAK
   - v2.1 cần parser upgrade Roslyn để track setter modifier
3. → VALUE_OBJECT_LEAK (severity SHOULD — VO immutability rule)

**Rule ID:** `DDD-CD16-003`

**Skip:**
- VOs marked `[Mutable]` attribute trong metadata (explicit exception)
- VOs trong `Eureka.Shared.Domain.Primitives/` (audited types như `AuditableValueObject`)

### Step CD16.5 — Anemic domain model (ANEMIC_DOMAIN_MODEL)

> Aggregate/Entity chỉ có properties getters/setters, không có business behavior methods.

**Logic:**
1. Iterate `nodes[]` filter `kind=aggregate_root OR kind=entity`:
   - Properties_count ≥ 5 (entity có substantial state)
   - VÀ check edges từ node: KHÔNG có edge `kind=raises_event` (không emit event)
   - VÀ heuristic name pattern: KHÔNG có method tên matching business verb (chỉ có constructor + getter/setter)
2. v1.0 limitation: graph parser KHÔNG track method names. Lane CD16 dùng heuristic indirect:
   - Aggregate KHÔNG raise event (raises_event edges = 0) AND properties_count ≥ 5
   - → suspect ANEMIC_DOMAIN_MODEL (severity MAY — code smell gợi ý)
3. Skip:
   - Reference data entities (Currency, Country, HsCode) — chấp nhận anemic vì là lookup
   - Read-side projections (Eureka.Modules.*.ReadModels/) — explicit anemic by design
   - DTOs trong Domain (vd `OrderSummary` projection)

**Rule ID:** `DDD-CD16-004`

| Tier | Check | Tool | Fail action |

| T1 | `signals.json` + `CD16-domain-logic-integrity-report.md` + `lane-status.json` exist | bash | **E044** — Output missing → auto-fix (re-run Step CD16.6-CD16.8 max 3) |

| T4 | `affected_entities[]` mỗi signal resolve được trong `be-domain-graph.json.nodes[].name` | jq | **E045** — Entity unresolved → log WARN (có thể là entity ngoài be-domain-graph scope), KHÔNG block |

```bash
# T1 — Output files exist
for f in signals.json CD16-domain-logic-integrity-report.md lane-status.json; do
  [ -f "$LANE_DIR/$f" ] || die "E044" "Output missing: $f"

# T2 — Schema valid
SCHEMA=$(jq -r '."$schema"' "$LANE_DIR/signals.json")
LANE_VAL=$(jq -r '.lane' "$LANE_DIR/signals.json")
[ "$SCHEMA" = "signals-v1" ] || die "E044" "Schema mismatch: $SCHEMA != signals-v1"
[ "$LANE_VAL" = "CD16" ] || die "E044" "Lane field mismatch: $LANE_VAL != CD16"

# Fingerprint dedup
FP_TOTAL=$(jq '.signals | length' "$LANE_DIR/signals.json")
FP_UNIQUE=$(jq '[.signals[].fingerprint] | unique | length' "$LANE_DIR/signals.json")
[ "$FP_TOTAL" = "$FP_UNIQUE" ] || die "E044" "Fingerprint collision: total=$FP_TOTAL unique=$FP_UNIQUE"

# T3 — Rule ID format

[ "$INVALID_RULES" = "0" ] || die "E045" "Invalid rule_id format count: $INVALID_RULES"

# T4 — Entity resolution (WARN only)
UNRESOLVED=$(jq -r --slurpfile g "$BE_DOMAIN_GRAPH" \
  '[.signals[] | .affected_entities[]?] | unique
   | map(select(. as $e | ($g[0].nodes | map(.name) | index($e)) == null))
   | length' "$LANE_DIR/signals.json")
[ "$UNRESOLVED" = "0" ] || log_warn "E045" "Unresolved entities count: $UNRESOLVED (có thể ngoài be-domain-graph scope)"
```
