## C1.4.1 — Mỗi dimension có signals.json ✅ PASS

**Evidence:**

- `lane_dispatch.py:476-478` — `_execute_lane_sequential()` creates `lane_dir = session_dir / "lanes" / dim` and `signals_path = lane_dir / "signals.json"` for every dim
- `lane_dispatch.py:584-610` — `_merge_static_signals()` + `_atomic_write_json()` writes signals.json with lock protection
- `signal_aggregator.py:86-92` — `aggregate_lane_signals()` iterates all dims, reads `lanes/{DIM}/signals.json`, skips with error if missing
- `lane_dispatch.py:484-488` — Early-fail returns `LaneResult(status="failed")` if `dimension.json` not found

**Architecture:** For every dimension in DIMS_ARRAY, the dispatch flow is:
1. Resolve probes from dimension.json
2. Create lane dir `lanes/{DIM}/`
3. Execute probes → collect signals
4. Atomic write signals.json with MERGE-PRESERVE lock

No path exists where a selected dim silently produces no signals.json without an error being recorded.

## C1.4.2 — probes_executed == probes_total ⚠️ WARN

**What works:**
- `lane_dispatch.py:504` — `probes_executed` is incremented for every successfully executed static probe
- `lane_dispatch.py:576` — `signals.json.probes_executed` records the count in the envelope
- `lane_dispatch.py:1200-1250` — `_sync_lane_status_totals()` syncs `lane-status.json.totals.probes_run`
- `phase1-engine.md:670-682` — POST-GATE T5.5 checks `probes_executed == 0` (zero-probes gate)
- `report_generator.py:45` — `probes_total` is a CLI parameter for reporting

**Gaps identified:**

1. **No automated `probes_executed == probes_total` comparison.** While `probes_total` exists as a concept (derivable from `dimension.json` probe count filtered by profile), there is no code that compares `probes_executed` against the expected total and flags the mismatch. POST-GATE T5.5 only catches the extreme case of `probes_executed == 0`.

2. **Stack-mismatch skips are untracked.** When `_is_probe_applicable_for_stack()` returns False (line 874), the probe returns `[]` without incrementing `probes_executed`. The skip has no trace — no `skip_reason` in `lane-status.json`, no entry in `probe-failures.log`. This means `probes_executed < probes_total` can occur silently.

3. **Non-static probes are not counted in lane_dispatch's `probes_executed`.** By design, non-static probes (runtime, agent, llm types) are executed by the orchestrator AFTER `lane_dispatch`. Lane dispatch only counts static probes. This is by design but means the `probes_executed` field in signals.json is partial until the orchestrator completes all non-static probes and updates the count.

**Recommendation:** Add a POST-GATE check comparing resolved probe IDs from `dimension.json` against probe IDs present in `signals.json.signals[].probe_id` (after all probes complete). Record stack-mismatch skips as `skip_reason: "stack_mismatch"` in `lane-status.json`.

## C1.4.4 — Stack-mismatch probes skip đúng cách ⚠️ WARN

**What works:**
- `lane_dispatch.py:231-253` — `_is_probe_applicable_for_stack()` correctly filters probes:
  - "any" in applicable_stacks → always run
  - stack == None (no detection) → fail open, run anyway
  - primary_stack match → run
  - secondary_stacks match → run
  - Otherwise → skip
- `lane_dispatch.py:861-875` — In `_execute_static_probe()`, stack-aware filter is applied
- `lane_dispatch.py:231` — Doc explicitly says "fail open" when stack info missing

**Gap: Skip is completely silent.**

When `_is_probe_applicable_for_stack()` returns False:
- `_execute_static_probe()` returns `[]` (line 875)
- `probes_executed` is NOT incremented (no probe was executed)
- No `skip_reason` is recorded in any file
- No entry in `probe-failures.log`
- No update to `lane-status.json`

**Impact:** On a TypeScript-React project (primary_stack=typescript-react), if dimension QD1 includes `P-QD1-python-endpoint-check` (applicable_stacks=python-fastapi/python-django), that probe is silently skipped. The `probes_executed` count will be 1 less than `probes_total` from `dimension.json`, but there's no explanation. A reviewer can't distinguish "probe failed silently" from "probe was intentionally skipped due to stack mismatch."

**Recommendation:** Log stack-mismatch skips with a `skip_reason: "stack_mismatch"` entry in `lane-status.json.skipped_probes[]` or emit an INFO-level line to stderr. This would allow POST-GATE to validate that `probes_executed + skipped_count == probes_total`.

## C1.4.5 — Static + non-static merge không mất dữ liệu ✅ PASS

**Architecture verified:**

| Writer | Scope | Lock |
|--------|-------|------|
| `lane_dispatch.py` (Python) | MERGE-write static probes, PRESERVE non-static | `_signals_lock_acquire()` |
| `signal-emit.md` (bash helper) | APPEND-only non-static signals | `acquire_signals_lock` (bash) |
| `merge_signals.py` (Python) | APPEND LLM signals, dedup by fingerprint | `_signals_lock_acquire()` |
| `signal_aggregator.py` (Python) | READ-ONLY for signals.json | None |

**Merge logic verified:**

1. **Static merge (lane_dispatch.py:1141-1197):**
   - Reads existing signals.json
   - Separates into: static_existing (replaced) + preserved (non-static kept)
   - Concatenates: preserved + new static signals
   - Logs preserved/replaced counts to stderr (line 592)

2. **LLM merge (merge_signals.py:142-214):**
   - Loads static signals.json + llm-signals.json + cross-signals
   - Dedup by fingerprint — static priority (LLM duplicates dropped)
   - Appends unique LLM signals
   - Updates envelope with `llm_merged`, `llm_signals_count`, `cross_signals_count`, `llm_dedup_dropped`

3. **Cross-language lock (lane_dispatch.py:1012-1068, merge_signals.py:48-91):**
   - Convention: `<signals_path>.lock/` directory (mkdir POSIX atomic)
   - Python and bash share same path → mutual exclusion
   - Stale takeover: 300s timeout

**Write Ownership Contract** (`phase1-engine.md:284-300`) clearly documents all 4 writers and their scope.

**No data loss path exists.** The MERGE-PRESERVE pattern ensures non-static signals survive static re-runs, and the lock prevents concurrent writes.
