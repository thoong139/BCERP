## C1.7 — Session Isolation & Concurrency Safety (5 CP)

### C1.7.1 — POSIX Lock Atomic → PASS

**Evidence:**
- `acquire_lock()` tại `.claude/scripts/wf-fix-common.sh:257-325`
- Dùng `.lock.acquiring/` **mkdir guard** — POSIX atomic: `mkdir` fail nếu directory đã tồn tại → single process wins
- Retry: mkdir fail → sleep 1s → retry 1 lần → nếu vẫn fail → ERROR return 1
- Stale guard cleanup: guard tồn tại > 120s (SIGKILL giữa mkdir và rmdir) → takeover
- Sau khi có guard: kiểm tra `.lock` hiện hữu → nếu age < 60min → ERROR; nếu age ≥ 60min → WARN + takeover
- `atomic_write_json` ghi lock metadata JSON
- Cleanup: `rmdir "$lock_guard"` ở mọi exit path

**Đánh giá:** Cơ chế đúng chuẩn POSIX. Race condition được xử lý ở 2 tầng: guard mkdir + stale takeover. Không có race window giữa check và write.

### C1.7.2 — Heartbeat Duy Trì Lock → PASS

**Evidence:**
- `start_heartbeat_daemon()` tại `.claude/scripts/wf-fix-common.sh:347-356`
- Spawn background process: `while [ -f "$session_dir/.lock" ]; do heartbeat_lock "$session_dir"; sleep "$WF_FIX_HEARTBEAT_INTERVAL_SEC"; done &`
- Default interval: **30s** (`MCV3_HEARTBEAT_INTERVAL_SEC`)
- Daemon tự thoát khi `.lock` bị xóa (release)
- PID lưu vào `.heartbeat.pid`
- `stop_heartbeat_daemon()` (line 359-370): kill PID từ pid file, idempotent
- `heartbeat_lock()` (line 328-337): cập nhật field `heartbeat` ISO timestamp + `atomic_write_json`

**Đánh giá:** Heartbeat daemon đảm bảo lock mtime được cập nhật mỗi 30s, ngăn stale takeover nhầm cho long-running phases (>60 phút). PID tracking cho phép cleanup chính xác.

### C1.7.4 — Trap Cleanup Khi Exit → PASS

**Evidence:**
- `session-dir.md` §4 (lines 140-148): defines `cleanup_session()` mandatory pattern
- Cleanup function: `stop_heartbeat_daemon + release_lock` (cả 2 idempotent)
- `trap cleanup_session EXIT INT TERM`

- Session-dir.md §5 line 191: `trap cleanup_session EXIT INT TERM` trong resume path
- §4 explicitly states: "Caller (SKILL.md Phase 0) PHAI register trap de cleanup"

**Coverage của trap:**
| Exit path | Trap fires? | Lock released? |
|-----------|-------------|----------------|
| Normal completion (Phase 6 done) | EXIT → yes | yes |
| User Ctrl+C | INT → yes | yes |
| `kill <pid>` (SIGTERM) | TERM → yes | yes |
| `kill -9 <pid>` (SIGKILL) | ❌ Cannot trap | ❌ — stale sau 60min, takeover được |
| Bash `set -e` error exit | EXIT → yes | yes |

**Đánh giá:** Trap pattern đúng. SIGKILL edge case được xử lý qua stale takeover (60min). Tất cả graceful exit paths có cleanup.

### C1.7.5 — Session Directory Isolation → PASS

**Evidence:**
- Session ID format: `YYYY-MM-DD-{scope}-{slug}-{NN}` (session-dir.md §1)
- Counter NN auto-increment qua `generate_session_id()` (wf-fix-common.sh:166-213)
- Atomic claim: `mkdir "$session_dir"` — nếu fail (slot đã có) → tăng counter → retry
- Overflow handling: >99 → 3-digit + WARN; >999 → ERROR
- Flat directory structure: `sessions/{session_id}/` — không nesting
- F21 fix (session-dir.md §2): combined gen+mkdir+lock+retry loop → max 5 attempts, sleep 50ms giữa retries
- Race scenario verified (session-dir.md §2 table): 2 concurrent processes get distinct SIDs

**Isolation properties:**
- Mỗi session có `sessions/{unique_id}/` riêng
- Lock file `.lock` riêng cho mỗi session dir
- Không có shared mutable state giữa các session dir
- `_index/sessions.jsonl` là append-only JSONL — multiple sessions write non-overlapping lines

**Đánh giá:** Isolation được đảm bảo ở 3 tầng: unique directory, per-session lock, append-only index. F21 retry loop xử lý edge case 2 process khởi tạo đồng thời.

## C1.8 — Graceful Degradation (5 CP)

### C1.8.1 — Thiếu Playwright (QD9 Browser Probes) → WARN

**Evidence:**
- QD9 skip mechanisms hiện tại:
  - `--no-browser` flag → skip toàn bộ browser probes
  - `interface_type == "api-only"` → QD9 bị skip (profiles.json:37, isg_recommender.py:491)
  - Profile `quick` → 0% runtime coverage (coverage_estimator.py:71)
- profiles.json line 37: `"skip_condition": "interface_type=api-only hoac --no-browser flag"`
- `SKILL.md` line 262: `BROWSER_REQUIRED_OVERRIDDEN=true` → QD9 skip tự động

**Gap identified:**
- **Không có runtime detection** của Playwright MCP availability
- Không có code path `skip_reason: "playwright_unavailable"`
- Nếu user chạy trên môi trường không có Playwright MCP nhưng **không** set `--no-browser` và `interface_type != api-only`:
  - QD9 sẽ được dispatch bình thường
  - Lane dispatch sẽ spawn Playwright probes
  - Agent sẽ fail khi gọi `mcp__plugin_playwright_playwright__*` (không có MCP server)
  - **Không có graceful degradation** — sẽ crash hoặc hang

**Đánh giá:** WARN. Hệ thống dựa vào user opt-in/opt-out thay vì auto-detect. Cần thêm pre-flight check: nếu `interface_type != api-only` và `--no-browser` không set → kiểm tra Playwright MCP có available không → nếu không → skip QD9 với `skip_reason: "playwright_unavailable"`.

## Observations

### OBS-017 — Playwright Unavailability Not Auto-Detected
- **Mức độ:** WARN
- **Mô tả:** QD9 browser probes yêu cầu Playwright MCP server. Hệ thống hiện tại không kiểm tra availability của Playwright MCP trước khi dispatch QD9. Skip chỉ dựa vào `--no-browser` flag, `interface_type=api-only`, hoặc profile. Nếu chạy trên môi trường không có Playwright MCP nhưng không có các flags trên, QD9 sẽ được dispatch và có thể crash khi agent cố gọi Playwright tools.
- **Đề xuất:** Thêm pre-flight check trong Phase 1 lane dispatch: phát hiện Playwright MCP availability → nếu unavailable và QD9 được chọn → log `skip_reason: "playwright_unavailable"` trong lane-status.json và skip QD9 probes gracefully.

### OBS-018 — New-Session Trap Registration Not Shown in Code Block
- **Mức độ:** MINOR (observation only)
- **Mô tả:** session-dir.md §2 (new-session path, line 96) shows `start_heartbeat_daemon` nhưng không hiển thị `trap cleanup_session EXIT INT TERM` trong cùng code block. Trap chỉ xuất hiện ở §4 (line 148) và resume path (line 191). Đây là documentation gap — không phải implementation bug.
- **Đề xuất:** Thêm 1 dòng `trap cleanup_session EXIT INT TERM` sau `start_heartbeat_daemon` trong code block ở §2 để nhất quán với §4 yêu cầu mandatory.

### OBS-019 — ci-detect.sh Lock Uses set -C (noclobber), Not mkdir Guard
- **Mức độ:** MINOR (observation only)
- **Mô tả:** `ci-detect.sh` sử dụng `set -C` (noclobber) cho file lock thay vì mkdir guard như `wf-fix-common.sh`. Cả 2 đều atomic trên POSIX filesystems, nhưng inconsistency giữa 2 lock mechanism có thể gây nhầm lẫn khi maintain. Tuy nhiên, khác biệt này có lý do: ci-detect.sh lock là short-lived file lock (không cần heartbeat), trong khi session lock là long-running directory guard.
- **Đánh giá:** Hợp lý về mặt kỹ thuật. Không cần sửa.
