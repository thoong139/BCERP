### E.2 — Write Throttle (5s per session)

**Pattern:**
- Module-level `_LAST_WRITE_TIME[session_key] → monotonic` + `_PENDING_STATE[session_key] → (session_dir, state)`.
- `_atomic_write_state(session_dir, state, force=False)`:
  - If `not force` AND `elapsed < 5s` AND `last_write > 0` → store in pending, skip disk.
  - Else → clear pending, write disk, update last-write timestamp.
- `read_scan_state(session_id)` prefers pending (deep-copied) over disk → view-of-truth stays consistent.
- Critical paths use `force=True`: `update_layer_status` (state transitions), `append_error`, `update_last_completed`.
- `flush_pending_writes(session_id=None)` + `atexit` handler ensure no loss on process exit.

**Tests added:** 7 × `TestWriteThrottle` — rapid non-critical ≤ 1 write, critical bypass, defer+flush, read-pending, per-session isolation.

### E.3 — Concurrency Controller

**New module:** `_shared/ips/concurrency_controller.py`

**API:**
```python
ctrl = ConcurrencyController(global_max=8, per_layer_max=3, per_probe_max=4, reserved_for_synthesis=2)
if ctrl.acquire(layer, probe_id, agent_key, timeout_sec=60):
    try: ... spawn ...
    finally: ctrl.release(layer, probe_id, agent_key)
else:
    ... timeout — retry/abort ...

ctrl.status()      # { global_in_use, per_layer, per_probe, active_agents[{key, held_sec}] }
ctrl.active_keys() # list[str]
```

**Implementation:**
- Single `threading.Lock()` + `threading.Condition()` — lock acquired only around state mutation; waiters sleep on condition with `timeout=remaining` for bounded wait.
- Non-synthesis layers see effective global cap = `global_max - reserved_for_synthesis`; L6 sees full `global_max`.
- Release idempotent (unknown key = no-op).
- Double-acquire detection raises `ValueError`.
- Singleton `get_default_controller()` / `reset_default_controller()`.

**Tests added:** 18 — basic roundtrip, 3-tier cap enforcement, reserved semantics, timeout (non-blocking + bounded + release-wake), 20-thread parallel stress asserts peak ≤ `global_max`, status/active_keys, validation, singleton.

### E.4 — Per-Agent Timeout + Watchdog

**New module:** `_shared/ips/agent_timeout.py`

**API:**
```python
timeout = resolve_timeout_sec(depth)
# depth in {deep, exhaustive} → 600s (or $LEGACY_SCAN_AGENT_TIMEOUT_DEEP_SEC)
# else                        → 300s (or $LEGACY_SCAN_AGENT_TIMEOUT_SEC)

reg = get_default_registry()
reg.register(key, layer, probe_id, depth=None, timeout_sec=None)
reg.check_expired(now=None) -> list[AgentEntry]
reg.mark_retry(key)   # attempt +1 (max 2), resets start_time
reg.mark_skipped(key) # pops + bumps skipped counter
reg.release(key)      # normal completion

# Tick helper for orchestrator loop:
watchdog_tick(reg, abort_fn, retry_fn, skip_fn, now=None)
# → {"aborted": N, "retried": M, "skipped": K}
```

**Policy per ADR-LS12 v2.1:**
- First timeout → abort + respawn simplified (attempt=2).
- Second timeout → abort + skip module + WARN.
- Invalid env var (non-float, ≤0) → falls back to default.

**Tests added:** 25 — env resolution (6), register/release (5), expiry (3), retry/skip state machine (5), watchdog_tick integration (3), status (2), singleton (1).

### E.5-E.7 — Scan Cache

**New module:** `_shared/ips/scan_cache.py`

**Fingerprint (per 04-data-model.md §7.2):**
```python
compute_fingerprint(
    probe_id="L3.inventory.screens",
    probe_version="1.0",
    depth="standard",
    config={"batch_size": 100},
    input_files=["src/a.ts", ...],
    dep_closure_files=["src/util/b.ts", ...],
)
# → "sha256:ab12cd34..."
```

**Sensitive to every input axis:** file hash, config hash, probe_version, depth, dep-closure. Missing-file marker `missing:<path>` keeps fingerprint stable across absence→presence transitions.

**2-tier cache:**
- Tier 1 session: `sessions/<id>/cache/` — ephemeral, auto under `.mc-data/` (gitignored).
- Tier 2 project: `.mc-data/cache/wf-legacy-scan/` — opt-in via `publish_to_project=True` (maps to `--cache-publish` CLI).
- Lookup: session → project → miss. Project hit promotes to session tier.
- Sharded layout `<root>/<2-char-prefix>/<fingerprint>.json` for directory-size hygiene.

**Invalidation rules (§7.4):**
- Automatic via fingerprint mismatch: file change, dep-closure change, probe version bump, config change, depth change.
- `invalidate(fingerprint)` — both tiers.
- `invalidate_pattern("L3.inventory.*")` — glob on `probe_id`.
- `invalidate_expired(now=None)` — TTL scan+delete (default 14d).
- `invalidate_by_probe_version(probe_id, minimum)` — version-bump flush.
- `no_cache=True` — disables get+set globally.

**Privacy guard (ADR-LS10):**
- `privacy_scope ∈ {secret, pii}` → never cached.
- Output key scan (depth ≤ 3) — regex matches `password`, `token`, `api[_-]?key`, `secret`, `private[_-]?key` → blocked.
- Matches both `api_key` and `apiKey`.

**Tests added:** 36 — fingerprint determinism + 5 sensitivity axes (7), privacy guard (6), backend CRUD + sharding (5), 2-tier lookup + promote + publish (4), privacy enforcement in cache (3), invalidation (5), `--no-cache` (2), factory (3), misc (1).

## Design Decisions

### DD-E.1 — Partial file separate from scan-state.json

**Alternative:** embed partial.json content inline under `scan-state.layers.<L>.partial`.
**Rejected:** partial.json can be written every file/feature (potentially hundreds per batch); embedding would contend with scan-state write throttle and bloat the JSON. Separate file under `layers/<L>/partial.json` sidesteps throttle and keeps scan-state.json small.

### DD-E.2 — Write throttle honors force flag

**Alternative:** throttle everything equally.
**Rejected:** layer status transitions (`not_started → in_progress → completed`) are the primitive that resume router uses; deferring them would cause crashes to report incorrect state. Critical paths (`update_layer_status`, `append_error`, `update_last_completed`) force-write; batch/module progress + partial writes go through throttle.

### DD-E.3 — read_scan_state prefers pending

**Alternative:** always read from disk.
**Rejected:** deferred writes accumulate in-memory; an `update_batch_progress` followed immediately by a read would see the pre-update disk state if we didn't inspect pending. Phase E makes `read_scan_state` return a deep copy of pending when available so that sequential update→read patterns stay consistent within a process.

### DD-E.4 — Concurrency controller standalone vs integrated into scan_state_reader

**Alternative:** embed acquire/release in scan_state_reader.
**Rejected:** `scan_state_reader` is state persistence; concurrency is resource scheduling. Separate module keeps responsibilities single and lets other skills (wf-fix-bugs v6 already uses similar pattern per ADR-LS12 "Reused pattern") adopt it independently.

### DD-E.5 — Multiprocessing for crash test (not bash `kill -9`)

**Alternative:** bash script that forks `/wf-legacy-scan` + `kill -9 $PID`.
**Rejected:** `/wf-legacy-scan` is orchestrated by Claude Agent (not a standalone process we can PID-kill from outside). Python `multiprocessing.Process` + `os._exit(9)` accurately simulates the durability stress: subprocess writes checkpoints, then hard-exits without cleanup; parent validates disk state. Atomic-rename write plus fsync means the filesystem sees either the old file or the new file — never a torn JSON. E2E that spawns actual Claude agents is deferred to Tier 2 manual (same rationale as D.9).
