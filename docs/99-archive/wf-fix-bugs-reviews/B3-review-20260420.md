## 2. [Góc độ 1] B3-1 Wire `/wf-fix-discover`

### 2.1 Tích hợp Signal Bus (ADR-04)

`wf-fix-discover/SKILL.md` Phase 1 POST-GATE emit `issue-registry.json` qua 2 cách:
- **Cách 2a (BẮT BUỘC khi probes emit Signal):** mỗi probe Layer 0/1/1a/4 + PASS 1-4 gọi `_shared.signal_bus.signal_bus.SignalBus.ingest()` hoặc CLI `python -m _shared.signal_bus.signal_bus ingest --signal-file ...`. POST-GATE gọi `flush` → bus merge + dedup + validate evidence (ADR-09) + chạy T1-T4.
- **Cách 2b (fallback):** direct write khi Signal Bus chưa wire đầy đủ / LPM minimal mode.

**issue_id ownership:** `wf-fix-discover` KHÔNG assign `issue_id` (set `null`); `wf-fix-triage` Step 2.0b là owner chính thức assign `ISSUE-001, ISSUE-002, ...`.

### 2.2 Tích hợp Scan Cache (ADR-19)

Phase 1 Layer 1 mỗi probe:
1. `compute_fingerprint(probe_id, probe_version, file_path, file_content_sha, config_hash)` → sha256 64 hex.
2. `lookup(cache_root, fp, current_file_sha)` — MISS → run probe → `set_entry(...)`; HIT → skip probe, copy cached signals.
3. **QD3 guard (ADR-22 rule 6):** `set_entry` raise `ValueError` NẾU bất kỳ signal có `dimension_hint="QD3"` — runtime guard từ B2 được respect đầy đủ.

**Opt-in:** chỉ kích hoạt khi `--use-cache`; TTL 14 ngày; cache path `.mc-data/cache/wf-fix-bugs/probes/<fingerprint>.json`.

### 2.3 Tích hợp Workload Estimator (ADR-14, ADR-15)

Phase 0 pre-scan:
- `workload_estimator.estimate(session_dir, profile, scope, selected_dims)` → `Workload` dataclass → emit `.mc-data/work/wf-fix-bugs/workloads/<workload-id>/fix-workload.json` (schema `fix-workload-v1`, atomic write).
- Flag `gate_triggered` (true nếu `total_estimated_sec > gate_threshold_sec`, default 2700s/45 min).
- `partition_plans[]` (`by_scope`, `by_dim`) cho Plan B hard-prompt.

### 2.4 Tích hợp Impact Graph Layer 0 (P0.XREF)

Phase 1 Layer 0 thêm probe `P0.XREF`:
- Gọi `_shared.impact_graph.builder.build(repo_root, scope, max_files=5000, max_file_bytes=1MiB)` → `Graph` dataclass → `_graph_to_dict(graph)` → emit `$SESSION_DIR/impact-graph.json` (schema `impact-graph.v1`).
- Hỗ trợ TS/TSX/JS/JSX + Py + Java/CS/Go/Rust (best-effort regex).
- Edge strength heuristic: base 0.5, +0.2 wildcard, +0.2 top-of-file eager (cap 1.0, floor 0.1).

**Cross-skill output path:** khớp `00-core.md §4b` dòng "wf-fix-discover Layer 0 (Impact Graph Builder — probe P0.XREF, v6.0+) → `$SESSION_DIR/impact-graph.json` → wf-fix-execute Phase 5 (Verify Ripple)".

### 2.5 Registry role

### 6.2 Step 1.5 — Workload Gate Check (ADR-14, ADR-15, CORE-027)

Sau Buoc 1 (Discover), orchestrator đọc `fix-workload.json` và quyết định theo Decision Matrix:

```
ratio = total_estimated_sec / gate_threshold_sec

IF gate_triggered == false OR ratio < 0.8  → DEAD-ZONE (chạy ngay)
ELIF 0.8 <= ratio <= 1.5                   → WARN (yes/no prompt)
ELIF ratio > 1.5                           → HARD-PROMPT / BLOCK (Plan A/B menu 5 options)
```

Plan A/B menu tiếng Việt (cho non-tech user), 6 lựa chọn (1-5 + 0 Dừng). Nếu user A4 (override) → auto CDG-03 token phải được user confirm ở Step 2.5. Nếu ABORT → log E024 + lưu resume command.

### 6.3 Step 2.5 — CDG Pre-Execute Handoff (Protocol 16, CORE-027)

Sau Buoc 2 (Triage), orchestrator quét `issue-registry.json.cdg_flags[]` + `fix-plan.md` markers `[CDG-0X]` + `workload_override=true` (if A4). Gom `$CDG_LIST = $CDG_ISSUES ∪ $CDG_MARKERS`.

- Rỗng → bỏ qua, sang Buoc 3.
- Không rỗng → render Protocol 16 §16.4 message template cho TỪNG CDG (hoặc batch theo §16.3 rule 6).
- User REJECT bất kỳ CDG critical (CDG-03/04/06/07) → ghi reject token, quay lại Buoc 2 re-plan.
- User ACCEPT tất cả → ghi `cdg-tokens.json` (schema `cdg-tokens-v1`, APPEND-only), UPDATE `fix-status.json.cdg_handoff = "passed"`.

### 6.4 Buoc 3 — Passthrough to `/wf-fix-execute`

`/wf-fix-execute` Phase 3 đọc `cdg-tokens.json` trước mỗi batch; nếu 1 issue CDG không có accept token → skill SKIP fix + move issue sang ESCALATE bucket.

`--dry-run` passthrough: `/wf-fix-execute` skip Phase 3-5, chạy Phase 6 preview; Step 2.5 cũng SKIP (log `[CDG] skipped (dry-run mode)`).
