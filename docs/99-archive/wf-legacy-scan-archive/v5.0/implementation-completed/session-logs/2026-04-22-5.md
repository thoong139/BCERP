## Design Decisions

### Dual-write transition (not hard cut-over)

Sub-skills CONTINUE writing ledger.json fields during v5.0 → v5.1 transition. Rationale:
- v4.1 orchestrators + downstream consumers still read ledger.json
- scan-state.json becomes **canonical** after golden test + Phase E/F land
- Eventual ledger.json reduction happens in Phase J (Migration + Docs)

### Defensive helper calls

Every helper call wrapped in try/WARN pattern. Sub-skill never blocks on helper IO failure.
Rationale: output files (classified/*, extracted/*) are the real value — skill must
produce them even if scan-state update fails due to e.g. session dir permission issue.

### IPS Phase B over $DOMAIN_EXPERTS

Phase 2 (extract) prefers `get_domain_expert_for_module()` helper over Phase 1 computed
`$DOMAIN_EXPERTS`. Rationale: helper reads `ips.phase_b.module_routing` which is the
authoritative source from IPS pipeline (Phase C). Phase 1 `$DOMAIN_EXPERTS` is fallback
when IPS data absent (e.g., v4.1 legacy migration).
