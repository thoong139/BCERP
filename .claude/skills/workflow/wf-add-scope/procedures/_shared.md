## 3. Safe-Write Protocol (CORE-006)

```
Fields OWNED by wf-add-scope: modules[], features[]
Fields NOT TOUCHED (không được modify):
  - project, systems[], departments[], requirements[], interface_type
  - design_status, ux_design_status, implementation_order
  - impl_status (per-REQ level)

QUY TẮC:
- APPEND-ONLY semantics — KHÔNG modify/delete/rename existing entries
- Idempotent — re-run an toàn, already-exist entries bị SKIP
- Atomic write — single atomic write cho toàn bộ JSON
- Validate post-write:
  * $systems_count_before == $systems_count_after
  * $modules_count_after == $modules_count_before + $modules_added
  * $features_count_after == $features_count_before + $features_added
  * All existing module/feature IDs still present (no deletions)
- Rollback on any check fail: restore từ $BACKUP_PATH
```

## 3.5 Session Isolation Protocol (v3.0+)

### Session ID Format

- **Pattern:** `{YYYY-MM-DD}-{sys-slug}`
- `sys-slug` = `$SYSTEM_ID` lowercase, kebab-case (ví dụ: `SYS-ERP-WEB` → `sys-erp-web`)
- **Ví dụ:** `2026-04-29-sys-erp-web`, `2026-04-29-sys-crm`
- **1 active session per (date, system)** — lock enforce, không counter suffix
- **Re-run cùng ngày cùng system:** CDG (resume vs replace vs cancel)

### Path Resolution

| Biến | Path |
|------|------|
| `$SESSION_DIR` | `.mc-data/work/wf-add-scope/sessions/$SESSION_ID/` |
| `$INDEX_FILE` | `.mc-data/work/wf-add-scope/_index/sessions.jsonl` |
| `$CACHE_DIR` | `.mc-data/work/wf-add-scope/_shared/cache/` |

Tất cả working files đều nằm trong `$SESSION_DIR/` — **KHÔNG flat**.

### Lock Mechanism

| Lock | Path | Hold time | Mục đích |
|------|------|-----------|---------|
| Session lock | `$SESSION_DIR/.session.lock` | Full session (~10-30 min) | Cross-host/cross-process conflict detection |
| Registry lock | `.mc-data/docs/_meta/.registry.lock` | < 30s (Phase 4 only) | Registry atomic write protection |

**Scripts:** `as-acquire-lock.sh` + `as-release-lock.sh` (`.claude/scripts/wf-add-scope/`)

### Heartbeat

- Daemon cập nhật `heartbeat_at` mỗi **30 giây** trong lock file
- **Stale threshold:** 60 phút (configurable: `MCV3_LOCK_STALE_MINUTES`)
- Cross-host stale → STOP E011 (không auto-takeover)
- Same-host stale (PID dead) → silent takeover
- Script: `as-heartbeat.sh` (background `nohup ... &`)

### Migration v2.0 → v3.0 (one-time)

- Detect: flat files `wf-add-scope/*.json` ngoài `sessions/`
- Action: move vào `sessions/_legacy-v2/<timestamp>/`
- Log: CORE-026 trace event `v2_to_v3_migration`
- **Graceful:** Nếu `sessions/` đã tồn tại → skip migration, tiếp tục bình thường

## 4. Module ID Naming Convention

- **Format:** `MOD-[SYS_SHORT]-[DOMAIN]`
- **SYS_SHORT:** drop `SYS-` prefix + drop dashes
  - `SYS-ERP-WEB` → `ERPWEB`
  - `SYS-MOBILE-STAFF` → `MSTAFF`
  - `SYS-BACKEND` → `BACKEND`
- **DOMAIN:** uppercase functional area — `CRM`, `ORDERS`, `WMS`, ...
- **Ví dụ đầy đủ:** `MOD-ERPWEB-CRM`, `MOD-MSTAFF-WMS`

## 5. Fix Rules

| Loại lỗi | Auto-Fix | Escalate nếu |
|-----------|----------|---------------|
| System ID không tồn tại | — | STOP E001 — không auto-create system |
| Module ID đã tồn tại | SKIP + log (→ `existing_conflicts[]`) | — (không phải lỗi) |
| Module name trùng (khác ID) | Rename với suffix `-2` | User từ chối rename |
| Feature ID trùng | SKIP + log | Conflict lan rộng |
| Registry JSON invalid sau write | Rollback từ `$BACKUP_PATH` | Backup không đọc được |
| Phase 2 doc stub path exists (non-stub content) | SKIP + log | — (không overwrite user content) |

## 6. Error Codes

| Code | Tình huống | Xử lý |
|------|------------|-------|
| E001 | System ID không tồn tại trong registry | STOP → liệt kê available systems → hỏi user. KHÔNG auto-create system (ngoài scope). |
| E002 | Thiếu `--from-mapping` / `--modules` / `--interactive` | STOP → yêu cầu user chọn 1 mode |
| E003 | `--from-mapping` nhưng không phải LEGACY_MODE | STOP → hướng dẫn chạy `/wf-legacy-scan` trước hoặc dùng `--interactive` |
| E004 | Registry JSON invalid khi đọc | STOP → yêu cầu user fix registry manually |
| E005 | Write failed / validation failed | ROLLBACK từ backup → STOP → log error chi tiết |
| E006 | All modules trong list đã tồn tại (0 new) | WARNING → exit cleanly với report "nothing to do" |
| E007 | Phase 2 stub path conflict với existing non-stub file | SKIP stub creation cho file đó + log warning. Không overwrite user content. |
| E008 | target-map.json not found hoặc missing consumer_hints (from-scan) | STOP → hướng dẫn ensure /wf-scan-target Sprint 5+ hoặc check path |
| E010 | Session đang chạy bởi process khác (lock_held_alive) | STOP → hiển thị PID + host đang giữ lock → hỏi user: chờ hoặc CDG force-cancel |
| E011 | Lock đang được giữ bởi host khác (lock_held_cross_host) | STOP → hiển thị host + lock age → hỏi user: đợi hoặc CDG takeover nếu biết chắc stale |
| E012 | Lock acquire failed — filesystem error | STOP → log full error → hướng dẫn check disk space + permissions tại `$WORK_ROOT` |

## 7. LEGACY_MODE Detection (CORE-021)

```bash
# Mechanism CHÍNH XÁC theo CORE-021 — KHÔNG dùng ledger.json (false positive)
test -f .mc-data/work/legacy-scan/project-context.md && \
  test $(wc -c < .mc-data/work/legacy-scan/project-context.md) -gt 500 && \
  echo "true" || echo "false"
```

**Downstream usage:**
- `$LEGACY_MODE == true` → Phase 2 chạy auto-detect features từ `module-code-mapping.json`
- `$LEGACY_MODE == false` → Phase 2 SKIP → features defer sang `/wf-define-features`
- `$FROM_MAPPING` yêu cầu `$LEGACY_MODE == true` → nếu không → STOP E003

## 8. Legacy Decisions Respect (CORE-022)

Nếu `.mc-data/work/wf-brainstorm/legacy-decisions.json` tồn tại:

```
deprecated_modules = jq '.deprecated_modules // []' legacy-decisions.json

FOR each module IN scope-spec.modules_to_add:
  IF module.id IN deprecated_modules:
    REMOVE module from modules_to_add
    LOG: "Module [module.id] is DEPRECATED per legacy-decisions.json — skipped"
```

**Graceful degradation:** Nếu file không tồn tại → tiếp tục với `deprecated_modules = []`, không block.

## 10. Execution Trace Pattern (CORE-026, Protocol 15)

```bash
# APPEND entry vào session-log.json — atomic jq write
# P1-7 fix: mktemp in same directory for same-filesystem atomic mv
tmp=$(mktemp ".mc-data/work/_trace/session-log.XXXXXX")
jq --arg skill "wf-add-scope" \
   --arg action "$ACTION" \
   --arg ts "$(date -Iseconds)" \
   --argjson details "$DETAILS_JSON" \
   '.entries += [{"skill": $skill, "action": $action, "timestamp": $ts, "details": $details}]' \
   .mc-data/work/_trace/session-log.json > "$tmp" && mv "$tmp" .mc-data/work/_trace/session-log.json
```

**Entries cần ghi:**
- `START` — Phase 0 khi init
- `COMPLETE` — Phase 6 khi kết thúc thành công
- `FAIL` — Bất kỳ phase nào khi STOP do error
