## §A Header

Lane CD41 **synth (tổng hợp)** test scenarios E2E từ violations + workflow-graph + business-invariants. Khác với 26 lanes v2.0 (đo coverage thuần tuý), CD41 là lane **PRODUCER** scenarios cho Phase 9 E2E Execute & Verify (v3.0 opt-in).

**Vì sao quan trọng:**
- 26 lanes Gói C++ Logistics phát hiện violation nhưng KHÔNG có khả năng tự verify runtime — phải dispatch qua wf-e2e-* legacy

**Filter logic (synth_filter trong _contract.json):**
- Violations: `severity ∈ {MUST, HIGH}`
- Dim subset: `dim ∈ {CD9, CD11, CD13, CD15, CD23, CD24, CD25, CD26, CD38, CD39}` (lanes liên quan UX / cross-module / business flow / UI coverage / error UX)

**Output (artifact-only — KHÔNG execute Playwright trong CD41):**

### Step CD41.2 — Filter & rank qualifying violations

> Input: `$QUALIFYING_SIGNALS_TMP` (đã filter MUST/HIGH + dim subset trong PRE-GATE T3)

**Logic:**
1. Dedup violations theo `fingerprint` (nếu nhiều lanes phát hiện cùng issue → 1 scenario)
2. Rank by `severity` (MUST trước HIGH) + `affected_modules.length` desc (cross-module ưu tiên synth)
3. Cap số scenarios per session (default 40 — tránh runtime Phase 9 quá dài; override qua `MCV3_CMI_CD41_MAX_SCENARIOS`)

```bash
MAX_SCENARIOS="${MCV3_CMI_CD41_MAX_SCENARIOS:-40}"

RANKED_VIOLATIONS_TMP="$SESSION_DIR/.cd41-ranked-violations.$$"

# Dedup theo fingerprint + rank theo severity desc + affected_modules.length desc
jq -s --slurp \
  '[.[] | . + {affected_mod_count: ((.affected_entities // []) | length)}]
   | unique_by(.fingerprint // .id)
   | sort_by(if .severity == "MUST" then 0 else 1 end, -(.affected_mod_count))
   | .[0:'"$MAX_SCENARIOS"']' \
  "$QUALIFYING_SIGNALS_TMP" > "$RANKED_VIOLATIONS_TMP" 2>/dev/null

# Fallback nếu jq slurp lỗi (file empty hoặc invalid)
if [ ! -s "$RANKED_VIOLATIONS_TMP" ]; then
  jq -s 'sort_by(if .severity == "MUST" then 0 else 1 end) | .[0:'"$MAX_SCENARIOS"']' \
    "$QUALIFYING_SIGNALS_TMP" > "$RANKED_VIOLATIONS_TMP"
fi

RANKED_COUNT=$(jq 'length' "$RANKED_VIOLATIONS_TMP")
log_info "CD41" "Ranked $RANKED_COUNT violations (cap=$MAX_SCENARIOS) for scenario synth"
```

### Step CD41.3 — Walk workflow-graph per violation để build flow path

> Đối với mỗi violation, lookup invariant + walk workflow-graph để tạo bước test logic.

**Logic per violation:**
1. Resolve `invariant_id` (nếu signal có ref) → `business-invariants.json.invariants[]` → `expression` + `modules_involved[]` + `source_doc`
2. Tìm `workflow-graph` paths involving modules (BFS từ entry node thuộc modules):
   - Entry node = first node có `module ∈ invariant.modules_involved`
   - Walk edges, max depth 8 (tránh path quá dài)
   - Confidence = `min(1.0, path_length / expected_length)` (expected_length từ invariant.complexity)
3. Tìm `api-graph` endpoints touched along path:
   - Cross-ref node `actions[]` với `api-endpoints[]` qua `endpoint_path` mapping
   - Collect required HTTP methods + path params
4. Tìm `fe-route-graph` UI routes user navigate:
   - Cross-ref module + action → route path (vd module=crm + action=create_customer → `/crm/customer/new`)
   - Nếu SSOT_AVAILABLE=true → ưu tiên `endpoint_classifications[].suggested_route`
5. Resolve actor (RBAC):
   - Nếu RBAC_AVAILABLE → tìm role có permission ứng với api endpoints → pick highest-privileged role với min perm
   - Fallback: actor=sysadmin

**Confidence scoring:**
- Path length 0 (no workflow walk possible) → `low_confidence`, mark scenario `skipped_low_confidence`, emit `E2E_SCENARIO_SKIPPED_LOW_CONFIDENCE`
- Path length ≥ 1 → confidence ≥ 0.5, synth scenario
- Path length ≥ expected (từ invariant) → confidence 1.0 (high quality)

```bash
# Per-violation processing (pseudo-bash — actual implementation đẩy sang Python helper hoặc inline jq script)
SYNTH_OUTPUT_TMP="$SESSION_DIR/.cd41-synth-output.$$"
> "$SYNTH_OUTPUT_TMP"

INDEX=1
while read -r violation; do
  [ -z "$violation" ] && continue

  INV_ID=$(echo "$violation" | jq -r '.invariant_ref // .source_invariant_id // empty')
  AFFECTED_MODULES=$(echo "$violation" | jq -c '.affected_entities // .affected_modules // []')
  VIOLATION_ID=$(echo "$violation" | jq -r '.id // .fingerprint')
  SEVERITY=$(echo "$violation" | jq -r '.severity')
  KIND=$(echo "$violation" | jq -r '.kind')
  SOURCE_DIM=$(echo "$violation" | jq -r '.source_dim // empty')

  # Lookup invariant (nếu có ref)
  if [ -n "$INV_ID" ]; then
    INV_EXPR=$(echo "$INV_BY_ID" | jq -r --arg id "$INV_ID" '.[$id].expression // empty')
    INV_MODULES=$(echo "$INV_BY_ID" | jq -c --arg id "$INV_ID" '.[$id].modules_involved // []')
  else
    INV_EXPR=""
    INV_MODULES=$AFFECTED_MODULES
  fi

  # Cross-module flag
  MODULE_COUNT=$(echo "$INV_MODULES" | jq 'length')
  CROSS_MODULE=$([ "$MODULE_COUNT" -gt 1 ] && echo "true" || echo "false")

  # Walk workflow-graph (delegate sang Python helper hoặc jq complex query)
  # Simplified inline jq: find nodes thuộc modules + sort by topological order
  WORKFLOW_NODES_FOR_INV=$(echo "$WORKFLOW_NODES" | jq -c --argjson mods "$INV_MODULES" \
    '[.[] | select(.module as $m | $mods | index($m))] | sort_by(.order // 0) | .[0:8]')
  PATH_LENGTH=$(echo "$WORKFLOW_NODES_FOR_INV" | jq 'length')

  # Resolve entry URL từ fe-route-graph (primary) hoặc SSOT (secondary) hoặc fallback /
  ENTRY_MODULE=$(echo "$INV_MODULES" | jq -r '.[0]')
  if [ "$CD41_MODE" = "browser" ]; then
    ENTRY_URL=$(echo "$FE_ROUTES" | jq -r --arg m "$ENTRY_MODULE" \
      '[.[] | select(.module == $m and (.route_type == "list" or .is_index == true))] | .[0].route_path // "/"' 2>/dev/null)
    [ -z "$ENTRY_URL" ] || [ "$ENTRY_URL" = "null" ] && ENTRY_URL="/${ENTRY_MODULE,,}"
  else
    # api-only mode: entry là API endpoint base
    ENTRY_URL=$(echo "$API_ENDPOINTS" | jq -r --arg m "$ENTRY_MODULE" \
      '[.[] | select(.module == $m)] | .[0].path // "/api/v1"' 2>/dev/null)
  fi

  # Resolve actor (RBAC matrix)
  if [ "$RBAC_AVAILABLE" = "true" ]; then
    ACTOR=$(jq -r --arg m "$ENTRY_MODULE" \
      '[.entries[] | select(.module == $m) | .role] | unique | .[0] // "sysadmin"' "$RBAC_MATRIX")
  else
    ACTOR="sysadmin"
  fi

  # Confidence
  if [ "$PATH_LENGTH" -eq 0 ]; then
    CONFIDENCE="low_confidence"
    SCENARIO_STATUS="skipped_low_confidence"
  elif [ "$PATH_LENGTH" -le 2 ]; then
    CONFIDENCE="medium"
    SCENARIO_STATUS="synthesized"
  else
    CONFIDENCE="high"
    SCENARIO_STATUS="synthesized"
  fi

  # Build synth record
  SCENARIO_ID=$(printf "CMI-SC-%03d" "$INDEX")
  SLUG=$(echo "${KIND}-${INV_ID:-na}" | tr '[:upper:] _' '[:lower:]--' | tr -cd 'a-z0-9-' | cut -c1-40)
  TITLE="${KIND}: ${INV_EXPR:-$VIOLATION_ID}"

  jq -n \
    --arg sid "$SCENARIO_ID" \
    --arg slug "$SLUG" \
    --arg title "$TITLE" \
    --arg vid "$VIOLATION_ID" \
    --arg iid "$INV_ID" \
    --arg invexpr "$INV_EXPR" \
    --arg sev "$SEVERITY" \
    --arg kind "$KIND" \
    --arg dim "$SOURCE_DIM" \
    --argjson modules "$INV_MODULES" \
    --argjson cross "$CROSS_MODULE" \
    --argjson path "$WORKFLOW_NODES_FOR_INV" \
    --arg entry "$ENTRY_URL" \
    --arg actor "$ACTOR" \
    --arg confidence "$CONFIDENCE" \
    --arg status "$SCENARIO_STATUS" \
    '{scenario_id: $sid, slug: $slug, title: $title, source_violation_id: $vid, source_invariant_id: $iid, invariant_expression: $invexpr, severity: $sev, signal_kind: $kind, source_dim: $dim, modules_involved: $modules, cross_module: $cross, workflow_path: $path, entry_url: $entry, actor: $actor, confidence: $confidence, scenario_status: $status}' \
    >> "$SYNTH_OUTPUT_TMP"

  INDEX=$((INDEX + 1))
done < <(jq -c '.[]' "$RANKED_VIOLATIONS_TMP")

SYNTH_COUNT=$(wc -l < "$SYNTH_OUTPUT_TMP")
SYNTH_SKIPPED=$(jq -s '[.[] | select(.scenario_status == "skipped_low_confidence")] | length' "$SYNTH_OUTPUT_TMP")
SYNTH_VALID=$((SYNTH_COUNT - SYNTH_SKIPPED))
SYNTH_CROSS=$(jq -s '[.[] | select(.cross_module == true and .scenario_status == "synthesized")] | length' "$SYNTH_OUTPUT_TMP")

log_phase_event "phase4_cd41" "INFO" \
  "{\"synth_total\":$SYNTH_COUNT,\"synth_valid\":$SYNTH_VALID,\"synth_skipped\":$SYNTH_SKIPPED,\"synth_cross_module\":$SYNTH_CROSS}"
```

```bash

  STEPS_TBL="${STEPS_TBL}$(printf "| %d | %s | %s |  | - |\n" "$N" "$ASSERT_TEXT" "$ASSERT_EXPECTED")"

  # Classify scenario type

    *VIOLATION*|*MUST_*) SCENARIO_TYPE="BusinessRule" ;;
    *PERMISSION*|*RBAC*|*AUTH*) SCENARIO_TYPE="Permission" ;;
    *VALIDATION*|*MISSING_*|*INVALID*) SCENARIO_TYPE="Validation" ;;
    *WORKFLOW*|*FLOW*) SCENARIO_TYPE="Cross-module" ;;
    *) SCENARIO_TYPE="Happy" ;;
  esac
  [ "$CROSS" = "true" ] && SCENARIO_TYPE="Cross-module"

  # Render full scenario với CMI metadata frontmatter
  cat > "$SCENARIO_TMP" <<EOF
---
scenario_id: $SCENARIO_ID
generated_by: wf-cmi v3.0 CD41
generated_at: $(date -Iseconds)
session_id: $SESSION_ID
source_violation_id: $VID
source_invariant_id: $IID
source_dim: $DIM
severity: $SEV
scenario_type: $SCENARIO_TYPE
modules_involved: $MODULES
cross_module: $CROSS
confidence: $CONFIDENCE
entry_url: $ENTRY
actor: $ACTOR
mode: $CD41_MODE
---
```
