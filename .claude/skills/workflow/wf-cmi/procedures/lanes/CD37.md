## §A Header

Lane CD37 đảm bảo **tuân thủ quy định pháp lý** cross-border logistics VN+CN+international trong ERP. Mỗi regulation declared trong `compliance-mapping.json` phải có:

- **owner_module** map vào ≥1 module trong codebase
- **requirements[]** map vào ≥1 entity/endpoint/process/code_pattern thực tế
- **evidence_required=true** → audit log table tồn tại + tracking compliance event
- **last_audited_at** trong threshold (default 365 ngày)
- **Specific rules enforced** trong code (vd Invoice immutable sau issue, PII encryption, OFAC screening)

**Vì sao compliance-critical ★★★:**
- **VN-TT78/2021**: Hóa đơn điện tử có mã cơ quan thuế — vi phạm = phạt + truy thu thuế
- **VN-PDPL 2023**: Bảo vệ dữ liệu cá nhân — fine up to 5% revenue + criminal liability
- **VN-VNACCS**: Tờ khai hải quan VNACCS — vi phạm = block thông quan
- **CN-Fapiao**: VAT special invoice TQ — vi phạm = cancel tax credit
- **CN-PIPL 2021**: Cross-border data transfer CN→VN cần CAC assessment — sai = block dữ liệu
- **GDPR**: EU customer right to access/erasure — fine 4% global revenue
- **OFAC**: Sanctions screening customer/vendor — vi phạm = US/EU fine + criminal

### Step CD37.2 — Compliance check coverage (MISSING_COMPLIANCE_CHECK)

> Mỗi regulation declared PHẢI có code path enforce (entity declared, endpoint, process, hoặc code_pattern).

**Logic:**
1. Iterate 3 jurisdictions (`regulations_vn`, `regulations_cn`, `regulations_international`):
   - Mỗi regulation có `owner_module` + `requirements[]`
2. Cross-ref `owner_module` với codebase modules (be-domain-graph aggregates, be-cqrs handlers):
   - Module KHÔNG tồn tại → MISSING_COMPLIANCE_CHECK (severity MUST — regulation orphan)
3. Iterate `requirements[]` — mỗi requirement có 1 trong các fields: `entity`, `endpoint`, `process`, `code_pattern`, `fields_required`:
   - Resolve theo type:
     - **entity** → find trong be-domain-graph kind=aggregate_root|entity matching name
     - **endpoint** → find trong api-graph routes matching pattern
     - **process** → find handler trong be-cqrs-graph matching name pattern (vd `BreachNotificationProcess` → handler tên `BreachNotification*Handler`)
     - **code_pattern** → Grep code repository cho pattern (vd `Invoice.Update() PHẢI throw IfStatus=issued`)
     - **fields_required** → check entity properties contain all required fields
   - Không resolve được → MISSING_COMPLIANCE_CHECK (severity = `requirement.severity` từ SSOT, default HIGH)

**Rule ID:** `COMP-CD37-001`

**Signal payload:**
```json
{
  "kind": "MISSING_COMPLIANCE_CHECK",
  "severity": "MUST",
  "category": "VIOLATION",
  "rule_id": "COMP-CD37-001",
  "message": "Regulation VN-TT78-2021 requirement TT78-001 (e-invoice tax authority code) KHÔNG có code path enforce — entity Invoice thiếu fields EInvoiceCode, TaxAuthorityVerifiedAt, QRCode.",
  "regulation_ref": "VN-TT78-2021",
  "requirement_id": "TT78-001",
  "affected_entities": ["Invoice"],
  "affected_modules": ["Finance"],
  "missing_fields": ["EInvoiceCode", "TaxAuthorityVerifiedAt", "QRCode"],
  "evidence": [{"source": "SSOT compliance-mapping.json", "path": "regulations_vn.VN-TT78-2021.requirements[0]"}],
  "suggested_action": "Thêm 3 properties vào Invoice aggregate (EInvoiceCode string, TaxAuthorityVerifiedAt DateTimeOffset?, QRCode string), tạo migration + integration với GDT-TVAN gateway theo TT78."
}
```

### Step CD37.3 — Regulatory rule violation (REGULATORY_RULE_VIOLATION)

> Code vi phạm rule cụ thể declared trong regulation (entity behavior, validation, state transition).

**Logic:**
1. Iterate `requirements[]` filter có `code_pattern` hoặc `validation` declared:
   - vd TT78-002 `Invoice.Update() PHẢI throw IfStatus=issued`
   - vd VAT-001 `allowed_rates: [0.00, 0.05, 0.08, 0.10]` cho VN VAT
   - vd FAPIAO-002 `allowed_rates: [0.00, 0.06, 0.09, 0.13]` cho CN VAT
2. Cross-ref code patterns vi phạm:
   - **State invariant**: Find method `Update`/`Modify` trong aggregate matching entity → check có throw guard `if (Status == issued) throw`
   - **Allowed values**: Grep enum/const definitions matching field (vd `VatRate.{0.05, 0.08, 0.10}`) → compare với `allowed_rates[]`
   - **Field pattern**: regex validation declared (vd VNACCS-002 `^\d{12}-\d{4}$`) → check FluentValidation rule tồn tại
3. Vi phạm pattern → REGULATORY_RULE_VIOLATION (severity = `requirement.severity`)
4. Loại trừ test fixtures (`**/Tests/**`, `**/*Test*.cs`)

**Rule ID:** `COMP-CD37-002`

**Note:** Lane KHÔNG runtime evaluate — chỉ static. Dynamic rate sources (vd database tax_rates table) → log INFO suggest manual review.

### Step CD37.4 — Personal data ungoverned (PERSONAL_DATA_UNGOVERNED)

> PII handling vi phạm VN-PDPL/GDPR/CN-PIPL (no consent, no audit log, no erasure endpoint, no encryption).

**Logic:**
1. Filter regulations PII-related (VN-PDPL-2023, GDPR, CN-PIPL-2021):
   - Extract entities scope (Customer, Employee từ scope[] hoặc requirements[].entity)
2. Per PII entity, check 4 governance dimensions:
   - **Consent capture**: requirement `PDPL-001` requires `ConsentTimestamp, ConsentVersion, ConsentScope` fields → cross-ref entity properties
   - **Right to erasure endpoint**: requirement `PDPL-002`/`GDPR-002` requires `DELETE /api/.../pii` hoặc `/forget` endpoint → cross-ref api-graph
   - **PII access log**: requirement `PDPL-003` requires `PiiAccessLog` entity → cross-ref be-domain-graph (overlap với CD29 PII_READ_NOT_LOGGED nhưng CD37 check structural existence chứ KHÔNG check call-site)
   - **Encryption at rest**: requirement `PDPL-004` requires PII fields encrypted (AES-256-GCM) → Grep `[Encrypted]|EncryptedColumn|ProtectedData|.Encrypt(` trên fields trong `requirement.fields[]`
3. Mỗi dimension thiếu → PERSONAL_DATA_UNGOVERNED (severity tùy regulation: CRITICAL cho consent + erasure, HIGH cho audit + encryption)

**Rule ID:** `COMP-CD37-003`

**Suggested action mẫu:** "Customer entity thiếu 3 fields PDPL: ConsentTimestamp (DateTimeOffset), ConsentVersion (string), ConsentScope (string[]). Tạo migration + cập nhật CustomerRegistrationCommandHandler validate consent trước khi save. Endpoint `DELETE /api/crm/customers/{id}/pii` cần expose."

### Step CD37.5 — Cross-border compliance gap (CROSS_BORDER_COMPLIANCE_GAP)

> Cross-border data transfer VN↔CN, VN↔EU vi phạm regulation (CN-PIPL CAC assessment, GDPR transfer rules, OFAC screening).

**Logic:**
1. Iterate cross-border regulations: CN-PIPL-2021 (CN→VN transfer), GDPR (EU→non-EU), OFAC-SANCTIONS (sanctions screening)
2. Detect cross-border data flows:
   - **CN-PIPL-001**: Find code patterns moving data CN customer → VN system (Grep `customer.region == "CN"`, `tenant.country == "CN"`, `CnDataExporter|CrossBorderTransfer`)
     - Check `CrossBorderDataTransferProcess` workflow tồn tại trong be-cqrs-graph
     - Check có `CACAssessmentResult` field hoặc `CACApprovalToken` validation
     - Thiếu → CROSS_BORDER_COMPLIANCE_GAP (severity MUST)
   - **GDPR-001**: Find endpoints export EU customer PII (`/api/.../pii-export`) → check có `[Authorize]` + EU customer scope filter
   - **OFAC-001**: Find customer/vendor activation flow (be-cqrs handlers `ActivateCustomerCommandHandler|ApproveVendorCommandHandler`) → check có call `_ofacService.Screen(|SanctionsScreeningProcess` trước khi activate
   - **OFAC-002**: Find recurring job (Hangfire/Quartz) re-screen sanctions (90 days frequency) → cross-ref `BackgroundService` hoặc job definition
3. Mỗi vi phạm → CROSS_BORDER_COMPLIANCE_GAP

**Rule ID:** `COMP-CD37-004`

**Note:** OFAC + EU regulations apply globally cho SaaS multi-tenant. CN-PIPL apply khi tenant có CN customer (`customer.country=CN` filter).

### Step CD37.6 — Compliance audit stale (COMPLIANCE_AUDIT_STALE)

> Regulation `last_audited_at` quá `max_days_since_audit` (default 365 ngày) → audit chưa update.

**Logic:**
1. Iterate 3 jurisdictions regulations
2. Per regulation, parse `last_audited_at` (ISO date) → compare với TODAY:
   - `days_since_audit = (TODAY - last_audited_at).days`
   - `days_since_audit > MAX_DAYS_AUDIT` → COMPLIANCE_AUDIT_STALE (severity MEDIUM)
3. Bonus check: `next_review_at` đã qua → severity HIGH (overdue review)
4. Bonus check: `expiry_date` trong vòng `WARN_EXPIRING_DAYS` (default 90) → log INFO RECOMMENDATION (proactive renewal)

**Rule ID:** `COMP-CD37-005`

**Suggested action mẫu:** "Regulation VN-LABOR-CODE-2019 last_audited_at = 2024-04-01, đã 766 ngày (>365). Yêu cầu compliance-expert + legal-expert chạy annual audit + update `last_audited_at` trong SSOT compliance-mapping.json. Xem `compliance_workflows.annual_regulatory_review` cho checklist."

| Tier | Check | Tool | Fail action |

| T4 | Mọi signal có `regulation_ref` resolve được trong SSOT (regulations_vn/cn/international keys) | jq | **E045** — Regulation unresolved → log WARN |

```bash
# T1 — Output files exist
for f in signals.json CD37-regulatory-compliance-report.md lane-status.json; do
  [ -f "$LANE_DIR/$f" ] || die "E044" "Output missing: $f"
done

# T2 — Schema valid

LANE_VAL=$(jq -r '.lane' "$LANE_DIR/signals.json")
[ "$SCHEMA" = "signals-v1" ] || die "E044" "Schema mismatch: $SCHEMA != signals-v1"

FP_UNIQUE=$(jq '[.signals[].fingerprint] | unique | length' "$LANE_DIR/signals.json")
[ "$FP_TOTAL" = "$FP_UNIQUE" ] || die "E044" "Fingerprint collision: total=$FP_TOTAL unique=$FP_UNIQUE"

# T3 — Rule ID format + SSOT mapping
INVALID_RULES=$(jq -r \
  '[.signals[] | select(.rule_id | test("^COMP-CD37-[0-9]{3}$") | not) | .rule_id] | length' \
  "$LANE_DIR/signals.json")
[ "$INVALID_RULES" = "0" ] || die "E143" "Invalid rule_id format count: $INVALID_RULES (must match COMP-CD37-NNN)"

# Rule ID resolution — COMP-CD37-NNN map to RULE-CD37-NNN trong SSOT
ORPHAN_RULES=$(jq -r --slurpfile ssot "$SSOT_COMPLIANCE" \
  '[.signals[].rule_id | sub("^COMP-"; "RULE-")] -
   ($ssot[0].validation_rules.rules | map(.id)) | length' \
  "$LANE_DIR/signals.json")
[ "$ORPHAN_RULES" = "0" ] || log_warn "E143" "Orphan rule_id count: $ORPHAN_RULES (rules thiếu trong SSOT validation_rules.rules)"

# T4 — Regulation_ref resolution (WARN only — signal có thể là cross-cutting không tham chiếu cụ thể regulation)
UNRESOLVED=$(jq -r --slurpfile ssot "$SSOT_COMPLIANCE" \
  '[.signals[] | select(.regulation_ref) | .regulation_ref] | unique
   | map(select(. as $r |
       (($ssot[0].regulations_vn // {}) | keys | index($r)) == null
       and (($ssot[0].regulations_cn // {}) | keys | index($r)) == null
       and (($ssot[0].regulations_international // {}) | keys | index($r)) == null))
   | length' "$LANE_DIR/signals.json")
[ "$UNRESOLVED" = "0" ] || log_warn "E045" "Unresolved regulation_ref count: $UNRESOLVED (có thể là regulation ngoài SSOT scope hoặc typo)"
```
