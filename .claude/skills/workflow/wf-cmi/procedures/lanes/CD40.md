## §A Header

Lane CD40 đảm bảo **tài liệu in/xuất nhất quán brand + đầy đủ dữ liệu** — logistics-critical do EUREKA-2026 phải sinh invoice (TT 78/2021/TT-BTC e-invoice VN), BOL bilingual VN+EN+CN, customs declaration VNACCS, packing list, COO. **Vì sao quan trọng (theo `print-export-templates.json` validation_rules):**
- `BRAND_LOGO_MISSING_DOC` (RULE-CD40-002, CRITICAL) → External-facing invoice/BOL thiếu logo + tax_code → vi phạm compliance + brand damage

### Step CD40.2 — Print template drift check (PRINT_TEMPLATE_DRIFT)

> Mỗi `doc_template` declared trong SSOT phải có file template thực tế trong project AND fields khớp `required_fields[]`.

**Logic:**
1. Iterate `SSOT_TEMPLATES[]` (vd `invoice-vn`, `bol`, `customs-declaration-vn`, `packing-list`, `coo`)
2. Cho mỗi template, resolve file path từ `template_path` field hoặc convention (`apps/backend/Templates/{doc_type}.html`)
3. Kiểm tra file tồn tại — không có → PRINT_TEMPLATE_DRIFT severity CRITICAL (compliance doc) hoặc HIGH (internal doc)
4. Nếu file tồn tại, parse template:
   - HTML/Liquid: regex tìm placeholder `{{field_name}}` hoặc `{{ field_name }}`
   - cshtml/razor: regex `@Model.FieldName`
   - XML: tag `<FieldName>`
5. So sánh extracted fields vs `SSOT.required_fields[]`:
   - Field thiếu trong template → PRINT_TEMPLATE_DRIFT (severity HIGH cho compliance, MEDIUM cho internal)
   - Field trong template nhưng KHÔNG trong required_fields[] → log INFO (extra field — có thể legacy hoặc decoration)

**Signal payload:**
```json
{
  "kind": "PRINT_TEMPLATE_DRIFT",
  "severity": "MUST",
  "category": "VIOLATION",
  "rule_id": "DOC-CD40-001",
  "ssot_rule_ref": "RULE-CD40-003",
  "message": "Template invoice-vn (apps/backend/Templates/invoice-vn.html) thiếu field 'cqt_code' bắt buộc theo Thông tư 78/2021/TT-BTC",
  "affected_entities": ["invoice-vn"],
  "affected_files": ["apps/backend/Templates/invoice-vn.html"],
  "evidence": [
    {"file": ".mc-data/docs/_meta/print-export-templates.json", "snippet": "templates[id=invoice-vn].required_fields[]: serial_no, cqt_code, signing_cert, issuer_tax_code, ..."},
    {"file": "apps/backend/Templates/invoice-vn.html", "snippet": "Detected placeholders: {{serial_no}}, {{issuer_tax_code}}, ... — thiếu {{cqt_code}}, {{signing_cert}}"}
  ],
  "suggested_action": "Thêm placeholder {{cqt_code}} và {{signing_cert}} vào template invoice-vn.html — đảm bảo TT 78/2021/TT-BTC compliance"
}
```

### Step CD40.3 — PDF font availability check (PDF_FONT_MISSING)

> VN/CN font phải bundled trong project hoặc cộng tác system fonts.

**Logic:**
1. Iterate `SSOT_TEMPLATES[]` filter `output_format="pdf"`
2. Cho mỗi PDF template, kiểm tra `fonts[]` array declared:
   - Vietnamese: `Times New Roman`, `Arial`, `Roboto Vietnamese`, `Arial Unicode MS`
   - Chinese: `SimSun`, `SimHei`, `Noto Sans CJK`, `Microsoft YaHei`
3. Cross-ref filesystem: scan `apps/backend/Fonts/`, `apps/backend/wwwroot/fonts/`, `node_modules/@fontsource/`
4. Font không tồn tại trong project AND không phải common system font → PDF_FONT_MISSING (severity CRITICAL cho VN/CN documents)
5. Special check: nếu template có locale VN nhưng `fonts[]` chỉ có ASCII font (Arial, Courier) → likely render lỗi diacritics → severity HIGH

**Rule ID:** `DOC-CD40-002`

**Note:** Common system fonts (Times New Roman, Arial) thường có sẵn trên server Windows/Linux — chỉ flag nếu fail explicit declared. EUREKA Linux container → cần bundle fonts (Liberation Sans + Noto CJK).

### Step CD40.4 — Excel formula integrity check (EXCEL_FORMULA_BROKEN)

> Cell reference trong formula phải tồn tại trong template structure.

**Logic:**
1. Iterate `SSOT_TEMPLATES[]` filter `output_format="xlsx"` OR `output_format="csv"`
2. Cho mỗi Excel template, parse `excel_formulas[]` (nếu có):
   - Vd `{cell: "F10", formula: "=SUM(F2:F9)"}` — cần F2-F9 tồn tại
   - Vd `{cell: "G15", formula: "=VLOOKUP(A15, ProductList, 2, FALSE)"}` — cần named range `ProductList`
3. Cross-ref structure_fields[] hoặc parse Excel file thực tế (nếu có .xlsx file):
   - Cell reference ngoài range → EXCEL_FORMULA_BROKEN
   - Named range không declared → EXCEL_FORMULA_BROKEN
4. CSV templates: check encoding declared = UTF-8 BOM (SSOT RULE-CD40-007 encoding_utf8_bom_for_csv)

**Rule ID:** `DOC-CD40-003`

**Note:** Severity HIGH — user open file Excel sẽ thấy `#REF!` error → confused + lost data. v2.1 có thể integrate ExcelJS để parse runtime, v1.0 chỉ static check.

### Step CD40.5 — Brand logo/identity check (BRAND_LOGO_MISSING_DOC)

> External-facing docs (invoice, BOL, COO) PHẢI có logo + tax_code + business_license + hotline.

**Logic:**
1. Iterate `SSOT_TEMPLATES[]` filter `audience="external"` HOẶC `audience="compliance"` (invoice/BOL/COO/customs)
2. Cho mỗi template, check branding fields cần có:
   - `{{company_logo}}` hoặc `<img src="...logo...">` — resolve image path → tồn tại trong BRAND_ASSETS_FOUND
   - `{{company_tax_code}}` hoặc hard-coded tax_code
   - `{{company_address}}`
   - `{{company_hotline}}` hoặc `{{company_email}}`
3. Thiếu 1+ → BRAND_LOGO_MISSING_DOC (severity CRITICAL cho external-facing logistics docs)
4. Cross-ref SSOT.branding{} — nếu SSOT có logo_path nhưng file không tồn tại → CRITICAL (mock data, deploy broken)

**Rule ID:** `DOC-CD40-004` (maps SSOT `RULE-CD40-002 branding_consistent`)

**EUREKA-specific:** Invoice + BOL bilingual VN+EN+CN — phải có CN translation cho receiver. Logo phải render ở header. Tax_code MST 13 chữ số. Business_license = giấy phép kinh doanh.

### Step CD40.6 — Export data mismatch UI check (EXPORT_DATA_MISMATCH_UI)

> Excel/CSV export endpoint trả N cột nhưng UI list view show M cột khác → user confused.

**Logic:**
1. Iterate `PDF_EXPORT_ENDPOINTS[]` filter `output_format="xlsx" OR "csv"`
2. Cho mỗi export endpoint, build:
   - Export columns: parse từ BE handler (dùng api-graph response_schema hoặc Grep DTO definition)
   - UI columns: cross-ref UI list page (vd `/customer` → `customer-list-table.tsx` columns config)
3. Compare 2 sets:
   - UI có cột "Tên khách hàng" nhưng export thiếu → EXPORT_DATA_MISMATCH_UI (severity MEDIUM)
   - Export có cột "internal_id" nhưng UI ẩn → INFO (intentional ẩn)
   - UI default sort by "created_at DESC" nhưng export không preserve → EXPORT_DATA_MISMATCH_UI severity MEDIUM
4. UI hidden columns (vd `<TableColumn hidden>`) → KHÔNG flag (intentional)

**Rule ID:** `DOC-CD40-005`

**Heuristic v1.0:** Match column name approximate (vd `customer_name` vs `Tên KH`) qua manual mapping hoặc i18n keys. v2.1 cải tiến với DTO type analysis.

## §D POST-GATE (T1→T4 + Auto-Fix)

| Tier | Check | Tool | Fail action |
|------|-------|------|-------------|
| T1 | 3 output files exist | bash | **E044** — Output missing → auto-fix retry x3 |
| T2 | `signals.json` schema = `signals-v1`, `lane` = "CD40", fingerprint unique | jq | **E044** — Schema invalid → re-build |

```bash
# T1
for f in signals.json CD40-print-export-consistency-report.md lane-status.json; do
  [ -f "$LANE_DIR/$f" ] || die "E044" "Output missing: $f"
done

# T2
SCHEMA=$(jq -r '."$schema"' "$LANE_DIR/signals.json")
LANE_VAL=$(jq -r '.lane' "$LANE_DIR/signals.json")
[ "$SCHEMA" = "signals-v1" ] || die "E044" "Schema mismatch"
[ "$LANE_VAL" = "CD40" ] || die "E044" "Lane field mismatch"

FP_TOTAL=$(jq '.signals | length' "$LANE_DIR/signals.json")
FP_UNIQUE=$(jq '[.signals[].fingerprint] | unique | length' "$LANE_DIR/signals.json")
[ "$FP_TOTAL" = "$FP_UNIQUE" ] || die "E044" "Fingerprint collision"

# T3
INVALID_RULES=$(jq -r '[.signals[] | select(.rule_id | test("^DOC-CD40-[0-9]{3}$") | not) | .rule_id] | length' "$LANE_DIR/signals.json")
[ "$INVALID_RULES" = "0" ] || die "E045" "Invalid rule_id format: $INVALID_RULES"

# T4 — SSOT ref resolution (WARN only, chỉ check nếu SSOT_AVAILABLE)
if [ "$SSOT_AVAILABLE" = "1" ]; then
  UNRESOLVED_REF=$(jq -r --slurpfile ssot "$SSOT_DOC" \
    '[.signals[] | .ssot_rule_ref // empty] | unique
     | map(select(. as $r | ($ssot[0].validation_rules.rules | map(.id) | index($r)) == null))
     | length' "$LANE_DIR/signals.json")
  [ "$UNRESOLVED_REF" = "0" ] || log_warn "E045" "Unresolved SSOT refs: $UNRESOLVED_REF"
fi
```
