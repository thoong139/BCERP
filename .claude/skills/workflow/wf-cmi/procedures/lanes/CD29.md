## §A Header

Lane CD29 đảm bảo **tính đầy đủ audit trail** cho các entities có giá trị nghiệp vụ + compliance trong ERP. Mỗi entity declared trong `audit-critical-entities.json` phải có:

- **audit_table** tồn tại trong DB schema (immutable, append-only, partitioned)
- **audit_required_actions** đều có code path ghi log (interceptor / EF SaveChanges hook / explicit call)
- **tracked_fields** được capture đầy đủ trong ChangedFields JSONB
- **PII access logging** cho mọi READ trên entity có `pii_fields[]` (VN-PDPL Điều 6 + GDPR Art. 30)
- **Immutability enforcement** — KHÔNG được có UPDATE/DELETE statement trên audit_table

**Vì sao compliance-critical:**
- VN-PDPL (Nghị định 13/2023/NĐ-CP): mọi truy cập PII PHẢI log → vi phạm = phạt hành chính
- VN-TT78/2021: Invoice issued KHÔNG được sửa → phải audit mọi attempt + credit note
- ISO 27001 + SOC 2: audit trail là control bắt buộc cho data integrity
- Anti-fraud (RoleAssignment, JournalEntry, PurchaseOrder): audit log là forensic evidence

### Step CD29.2 — Audit table existence (MISSING_AUDIT_TABLE)

> Mỗi entity declared trong `audit_critical_entities{}` PHẢI có `audit_table` tồn tại trong DB schema (be-db-schema-graph).

**Logic:**
1. Iterate `audit_critical_entities{}` từ SSOT — mỗi entry có `audit_table` (vd `crm.audit_customer_log`)
2. Cross-ref `be-db-schema-graph.json.tables[]`:
   - Resolve full table name (schema + name) — handle case insensitive matching
   - Không tìm thấy → MISSING_AUDIT_TABLE (severity **MUST** — CRITICAL compliance gap)
3. Khi tìm thấy, verify table có required columns theo `audit_log_schema.required_columns[]` (Id, Timestamp, EntityType, EntityId, Action, ActorUserId, ChangedFields, CorrelationId, TenantId)

**Signal payload:**
```json
{
  "kind": "MISSING_AUDIT_TABLE",
  "severity": "MUST",
  "category": "VIOLATION",
  "rule_id": "AUDIT-CD29-001",
  "message": "Entity Customer (CRM) declared audit-critical nhưng audit_table crm.audit_customer_log KHÔNG tồn tại trong DB schema. Vi phạm compliance VN-PDPL + GDPR.",
  "affected_entities": ["Customer"],
  "affected_modules": ["CRM"],
  "expected_table": "crm.audit_customer_log",
  "evidence": [{"source": "SSOT audit-critical-entities.json", "entity_path": "audit_critical_entities.Customer.audit_table"}],
  "suggested_action": "Tạo migration mới: CREATE TABLE crm.audit_customer_log với 11 columns chuẩn (xem audit_log_schema.required_columns) + indexes (EntityType+EntityId+Timestamp DESC) + constraints NO UPDATE/DELETE."
}
```

### Step CD29.3 — Action coverage (AUDIT_ACTION_NOT_IMPLEMENTED)

> Mỗi action trong `audit_required_actions[]` PHẢI có code path ghi audit log (CQRS handler hoặc interceptor).

**Logic:**
1. Iterate `audit_critical_entities[].audit_required_actions[]` — mỗi entry: vd `{entity: Invoice, action: "ISSUE"}`
2. Cross-ref `be-cqrs-graph.json.request_handlers[]`:
   - Resolve handler tên matching pattern `{Action}{Entity}CommandHandler` (vd `IssueInvoiceCommandHandler`)
   - Grep handler body cho audit logging calls: `AuditLog.Add(|_auditService.Record(|_auditWriter.Append(|IAuditableEntity|AuditTrailInterceptor`
3. Không tìm thấy audit call trong handler → AUDIT_ACTION_NOT_IMPLEMENTED (severity MUST)
4. Loại trừ actions có generic interceptor (vd `AuditableEntitySaveInterceptor` chạy cho mọi SaveChanges) — kiểm tra trong DI registration

**Rule ID:** `AUDIT-CD29-002`

**Suggested action mẫu:** "Thêm `_auditWriter.Append(...)` trong `IssueInvoiceCommandHandler` trước khi `SaveChanges()`, hoặc đảm bảo `AuditableEntitySaveInterceptor` registered và Invoice implement `IAuditableEntity`."

### Step CD29.4 — Immutability violation (AUDIT_MUTABILITY_VIOLATION)

> `audit_table` KHÔNG được có UPDATE hoặc DELETE statement trong code (append-only).

**Logic:**
1. Iterate `audit_critical_entities[].audit_table` — list audit tables (vd `[crm.audit_customer_log, finance.audit_invoice_log, ...]`)
2. Grep code patterns vi phạm (CI: Serena `find_references` audit table name, fallback Grep):
   - SQL: `UPDATE crm.audit_customer_log|DELETE FROM crm.audit_customer_log|TRUNCATE crm.audit_customer_log`
   - EF Core: `_context.AuditCustomerLogs.Update(|.Remove(|.RemoveRange(`
   - Migration files: `migrationBuilder.UpdateData(table:"audit_|migrationBuilder.DeleteData(table:"audit_`
3. Loại trừ pattern hợp lệ:
   - Archive job `DELETE FROM audit_* WHERE Timestamp < @retention_cutoff` (data lifecycle management, allowed)
   - Test fixtures (path `**/Tests/**`, `**/*Test*.cs`)
4. Pattern match ≥1 → AUDIT_MUTABILITY_VIOLATION (severity **MUST** — phá vỡ forensic integrity)

**Rule ID:** `AUDIT-CD29-003`

**Note:** Lane KHÔNG runtime evaluate — chỉ static scan. Edge cases dynamic SQL → log INFO suggest manual review.

### Step CD29.5 — Tracked fields capture (TRACKED_FIELD_NOT_CAPTURED)

> Mọi `tracked_fields[]` declared PHẢI được capture trong audit log entry khi entity thay đổi.

**Logic:**
1. Iterate `audit_critical_entities[].tracked_fields[]` — vd Customer.tracked_fields = ["Name", "TaxCode", "Email", ...]
2. Cross-ref `be-domain-graph.json`:
   - Resolve entity properties (kind=aggregate_root|entity, name=entity_name)
   - Compare với tracked_fields[] — properties tồn tại nhưng KHÔNG trong tracked_fields → low confidence INFO (có thể intentional skip)
   - tracked_fields[] có field KHÔNG tồn tại trong entity → TRACKED_FIELD_NOT_CAPTURED (severity HIGH — SSOT outdated hoặc field renamed)
3. Cross-ref handler body (Grep `ChangedFields|TrackChange|RecordChange`):
   - Static analysis: handler có Update logic trên field thuộc tracked_fields[] nhưng KHÔNG explicit add field vào ChangedFields → AUDIT_FIELD_NOT_CAPTURED (severity SHOULD — runtime gap)
   - Nếu dùng auto-tracking interceptor (`EntityFrameworkAuditInterceptor` với `[Auditable]` attribute) → check entity class có attribute trên tracked fields

**Rule ID:** `AUDIT-CD29-004`

### Step CD29.6 — PII access logging (PII_READ_NOT_LOGGED)

> Entity có `pii_fields[]` → mỗi READ access PHẢI ghi `pii_access_log` entry (VN-PDPL Điều 6 + GDPR Art. 30).

**Logic:**
1. Iterate `audit_critical_entities{}` filter có `pii_fields[]` non-empty (vd Customer.pii_fields = ["TaxCode", "Email", "Phone", "Address"])
2. Resolve API endpoints liên quan entity (READ operations):
   - Cross-ref `api-graph.json` filter `method=GET AND route matching /api/.../{entity_lowercase_plural}` (vd `/api/crm/customers`, `/api/crm/customers/{id}`)
   - Filter `EXPORT_CSV|EXPORT_PDF` endpoints (Grep `[HttpGet("export")]|FileStreamResult|CsvHelper`)
3. Cross-ref controller/handler body cho PII access log call:
   - Pattern: `_piiAuditService.LogAccess(|PiiAccessLog.Add(|_auditWriter.RecordPiiRead(|[LogPiiAccess]`
   - Không tìm thấy → PII_READ_NOT_LOGGED (severity **MUST** — vi phạm VN-PDPL + GDPR)
4. Verify `pii_access_logging.required_fields[]` từ SSOT đủ trong handler call (AccessorUserId, EntityType, EntityId, AccessType, Purpose, CorrelationId)

**Rule ID:** `AUDIT-CD29-005`

**Suggested action mẫu:** "Thêm `_piiAuditService.LogAccess(new PiiAccessEntry { ... })` trong `GetCustomerByIdQueryHandler.Handle()` trước khi return DTO. Endpoint export PHẢI log AccessType=EXPORT_CSV với CorrelationId từ request context."

## §D POST-GATE (T1→T4 + Auto-Fix)

| Tier | Check | Tool | Fail action |
|------|-------|------|-------------|
| T1 | `signals.json` + `CD29-audit-trail-report.md` + `lane-status.json` exist | bash | **E044** — Output missing → auto-fix (re-run Step CD29.7-CD29.9 max 3) |
| T2 | `signals.json` schema = `signals-v1`, `lane` = "CD29", all signals có `fingerprint` unique | jq | **E044** — Schema invalid → auto-fix re-build từ raw signals |
| T3 | Mọi signal `rule_id` match format `AUDIT-CD29-\d{3}` AND tồn tại trong SSOT `validation_rules.rules[].id` (sau khi map AUDIT-CD29-NNN ↔ RULE-CD29-NNN) | jq | **E145** — Rule_id orphan → ESCALATE (signal false positive hoặc SSOT thiếu rule) |
| T4 | `affected_entities[]` mỗi signal resolve được trong `audit_critical_entities{}` keys | jq | **E045** — Entity unresolved → log WARN (có thể là entity ngoài SSOT scope), KHÔNG block |

```bash
# T1 — Output files exist
for f in signals.json CD29-audit-trail-report.md lane-status.json; do
  [ -f "$LANE_DIR/$f" ] || die "E044" "Output missing: $f"
done

# T2 — Schema valid
SCHEMA=$(jq -r '."$schema"' "$LANE_DIR/signals.json")
LANE_VAL=$(jq -r '.lane' "$LANE_DIR/signals.json")
[ "$SCHEMA" = "signals-v1" ] || die "E044" "Schema mismatch: $SCHEMA != signals-v1"
[ "$LANE_VAL" = "CD29" ] || die "E044" "Lane field mismatch: $LANE_VAL != CD29"

# Fingerprint dedup
FP_TOTAL=$(jq '.signals | length' "$LANE_DIR/signals.json")
FP_UNIQUE=$(jq '[.signals[].fingerprint] | unique | length' "$LANE_DIR/signals.json")
[ "$FP_TOTAL" = "$FP_UNIQUE" ] || die "E044" "Fingerprint collision: total=$FP_TOTAL unique=$FP_UNIQUE"

# T3 — Rule ID format + SSOT mapping
INVALID_RULES=$(jq -r \
  '[.signals[] | select(.rule_id | test("^AUDIT-CD29-[0-9]{3}$") | not) | .rule_id] | length' \
  "$LANE_DIR/signals.json")
[ "$INVALID_RULES" = "0" ] || die "E145" "Invalid rule_id format count: $INVALID_RULES (must match AUDIT-CD29-NNN)"

# Rule ID resolution — AUDIT-CD29-NNN map to RULE-CD29-NNN trong SSOT (vd AUDIT-CD29-001 ↔ RULE-CD29-001)
ORPHAN_RULES=$(jq -r --slurpfile ssot "$SSOT_AUDIT" \
  '[.signals[].rule_id | sub("^AUDIT-"; "RULE-")] -
   ($ssot[0].validation_rules.rules | map(.id)) | length' \
  "$LANE_DIR/signals.json")
[ "$ORPHAN_RULES" = "0" ] || log_warn "E145" "Orphan rule_id count: $ORPHAN_RULES (rules thiếu trong SSOT validation_rules.rules)"

# T4 — Entity resolution (WARN only)
UNRESOLVED=$(jq -r --slurpfile ssot "$SSOT_AUDIT" \
  '[.signals[] | .affected_entities[]?] | unique
   | map(select(. as $e | ($ssot[0].audit_critical_entities | keys | index($e)) == null))
   | length' "$LANE_DIR/signals.json")
[ "$UNRESOLVED" = "0" ] || log_warn "E045" "Unresolved entities count: $UNRESOLVED (có thể ngoài SSOT audit_critical_entities scope)"
```
