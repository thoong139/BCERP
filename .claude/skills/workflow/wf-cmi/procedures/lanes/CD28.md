### Step CD28.2 — Canonical ownership check (DUPLICATE_MASTER_ENTITY)

> Mỗi master entity có **đúng 1 owner_module** trong `be-domain-graph.json` (kind=aggregate_root).
> Modules khác CHỈ tham chiếu qua FK, KHÔNG được redefine AggregateRoot trùng tên.

**Logic:**
1. Iterate `master_entities{}` từ SSOT — mỗi entry có `entity_name` + `owner_module`
2. Cross-ref `be-domain-graph.json` filter `kind=aggregate_root`:
   - Đếm số module chứa AggregateRoot tên = `entity_name`
   - Nếu count > 1 → DUPLICATE_MASTER_ENTITY (severity HIGH)
3. Nếu owner_module trong SSOT KHÁC module thực tế chứa AggregateRoot → DUPLICATE_MASTER_ENTITY với `mismatch_owner`

**Signal payload:**
```json
{
  "kind": "DUPLICATE_MASTER_ENTITY",
  "severity": "MUST",
  "category": "VIOLATION",
  "rule_id": "MDM-CD28-001",
  "message": "Entity Customer được định nghĩa trong 2 modules: Crm + Sales (vi phạm canonical ownership)",
  "affected_entities": ["Customer"],
  "affected_files": ["apps/backend/Eureka.Modules.Crm/Customers/Customer.cs", "apps/backend/Eureka.Modules.Sales/Customers/Customer.cs"],
  "evidence": [{"file": "...", "line": 12, "snippet": "public class Customer : AggregateRoot"}],
  "suggested_action": "Giữ AggregateRoot tại Eureka.Modules.Crm; chuyển Sales.Customer thành value-object snapshot hoặc FK reference."
}
```

### Step CD28.3 — Unique key integrity (MISSING_UNIQUE_CONSTRAINT, PARTIAL_UNIQUE_CONSTRAINT)

> Mỗi `unique_keys[]` declared trong SSOT phải có UNIQUE constraint trong DB schema.

**Logic:**
1. Iterate `master_entities[].unique_keys[]` — mỗi entry: `{table_name, columns[], scope}` (vd Customer.tax_code unique national)
2. Cross-ref `be-db-schema-graph.json.indexes[]`:
   - Find index with `table=table_name`, `unique=true`, `columns ⊇ declared columns`
   - Không tìm thấy → MISSING_UNIQUE_CONSTRAINT (severity MUST — CRITICAL duplicate risk)
3. Nếu DB có UNIQUE index nhưng chỉ trên SUBSET columns (vd declared composite [tax_code, country] nhưng DB chỉ unique tax_code) → PARTIAL_UNIQUE_CONSTRAINT (severity SHOULD)

**Rule IDs:** `MDM-CD28-002` (missing) | `MDM-CD28-003` (partial)

### Step CD28.4 — Multi-writer detection (UNAUTHORIZED_MASTER_WRITER)

> Chỉ `owner_module` được phép CREATE entity master. Module khác CREATE = bypass MDM governance.

**Logic:**
1. Iterate `master_entities{}` — mỗi entry có `owner_module`
2. Cross-ref `api-graph.json` filter POST endpoints với route segment matching entity (vd `/api/customers`, `/api/crm/customers`):
   - Resolve module từ controller path (vd `Eureka.Modules.Sales.Controllers.CustomersController` → module=Sales)
   - Nếu module ≠ owner_module AND module ∉ `ownership_rules.create_allowed_modules[]` → UNAUTHORIZED_MASTER_WRITER (severity MUST)
3. PUT/PATCH endpoints → check `ownership_rules.update_allowed_modules[]` (vd Sales được update Customer.credit_limit nhưng KHÔNG create) — ngoài list → UNAUTHORIZED_MASTER_WRITER (severity SHOULD)

**Rule ID:** `MDM-CD28-004`

**Suggested action mẫu:** "Move POST `/api/sales/customers` to Eureka.Modules.Crm hoặc thêm Sales vào `ownership_rules.create_allowed_modules` (cần justification compliance)."

### Step CD28.5 — Reference data drift (REFERENCE_DATA_DRIFT)

> Reference data (HS Code, Currency, Country) phải có 1 source-of-truth.

**Logic:**
1. Iterate `reference_data{}` từ SSOT — mỗi entry: `{name, source_file|source_table, kind}` (vd HSCode source=`apps/backend/Eureka.Customs/Data/HsCodes.json`)
2. Glob filesystem cho copies:
   - `Glob "apps/backend/**/SeedData/**/*.{json,csv,xml}"` filter content match reference data name
   - `Grep "enum.*HsCode|enum.*Currency|enum.*Country"` cross-modules
3. Nếu tìm thấy >1 file/enum chứa cùng reference data → REFERENCE_DATA_DRIFT (severity HIGH)
4. Cross-validate values: parse 2+ sources và diff key set → flag rows mismatch

**Rule ID:** `MDM-CD28-005`

**Note:** Modules khác CHỈ được dùng reference data qua interface/service từ owner module — KHÔNG hardcode enum local.

### Step CD28.6 — Cross-module sync mechanism (MISSING_MDM_SYNC)

> Mỗi `sync_rules{}` declared (vd Customer sync CRM → AR within 5 min) phải có handler thực tế.

**Logic:**
1. Iterate `sync_rules[]` từ SSOT — mỗi entry: `{source_module, target_module, entity, mechanism: event|scheduled|api, max_lag_sec}`
2. Cross-ref by mechanism:
   - `event`: Find event handler trong `be-cqrs-graph.json.notification_handlers[]` matching event_name
   - `scheduled`: Grep `IHostedService|BackgroundService|Quartz|Hangfire` matching entity name
   - `api`: Check `api-graph.json` có endpoint `POST /api/.../sync` hoặc webhook
3. Không tìm thấy mechanism → MISSING_MDM_SYNC (severity tùy `max_lag_sec`: ≤60s=MUST, ≤300s=SHOULD, ngoài=MAY)

**Rule ID:** `MDM-CD28-006`

    "session_id": $sid,
    "generated_at": $ts,
    "lane": $lane,

    "scope": {"type": $scope_type, "modules": $modules_covered},
    "status": "COMPLETED",
    "scan_duration_sec": ($scan_duration | tonumber),
    "signals": $signals,
    "metadata": {
      "signal_count": ($signals | length),
      "severity_breakdown": {
        "MUST": ([$signals[] | select(.severity == "MUST")] | length),
        "SHOULD": ([$signals[] | select(.severity == "SHOULD")] | length),
        "MAY": ([$signals[] | select(.severity == "MAY")] | length),
        "INFO": ([$signals[] | select(.severity == "INFO")] | length)
      },
      "category_breakdown": {
        "MISSING_INVARIANT": ([$signals[] | select(.category == "MISSING_INVARIANT")] | length),
        "VIOLATION": ([$signals[] | select(.category == "VIOLATION")] | length),
        "GAP": ([$signals[] | select(.category == "GAP")] | length),
        "RECOMMENDATION": ([$signals[] | select(.category == "RECOMMENDATION")] | length)

      "modules_covered": $modules_covered,

      "fallback_used": false

| T4 | `affected_entities[]` mỗi signal resolve được trong `mdm-canonical-entities.json.master_entities{}` HOẶC `reference_data{}` | jq | **E045** — Entity unresolved → log WARN (có thể là entity ngoài SSOT scope), KHÔNG block |

```bash
# T1 — Output files exist
for f in signals.json CD28-mdm-consistency-report.md lane-status.json; do
  [ -f "$LANE_DIR/$f" ] || die "E044" "Output missing: $f"
done

# T2 — Schema valid
SCHEMA=$(jq -r '."$schema"' "$LANE_DIR/signals.json")
LANE_VAL=$(jq -r '.lane' "$LANE_DIR/signals.json")
[ "$SCHEMA" = "signals-v1" ] || die "E044" "Schema mismatch: $SCHEMA != signals-v1"
[ "$LANE_VAL" = "CD28" ] || die "E044" "Lane field mismatch: $LANE_VAL != CD28"

# Fingerprint dedup
FP_TOTAL=$(jq '.signals | length' "$LANE_DIR/signals.json")
FP_UNIQUE=$(jq '[.signals[].fingerprint] | unique | length' "$LANE_DIR/signals.json")
[ "$FP_TOTAL" = "$FP_UNIQUE" ] || die "E044" "Fingerprint collision: total=$FP_TOTAL unique=$FP_UNIQUE"

# T3 — Rule ID format + SSOT mapping
INVALID_RULES=$(jq -r --slurpfile ssot "$SSOT_MDM" \
  '[.signals[] | select(.rule_id | test("^MDM-CD28-[0-9]{3}$") | not) | .rule_id] | length' \
  "$LANE_DIR/signals.json")
[ "$INVALID_RULES" = "0" ] || die "E141" "Invalid rule_id format count: $INVALID_RULES"

ORPHAN_RULES=$(jq -r --slurpfile ssot "$SSOT_MDM" \
  '[.signals[].rule_id] - ($ssot[0].validation_rules | map(.id)) | length' \
  "$LANE_DIR/signals.json")
[ "$ORPHAN_RULES" = "0" ] || log_warn "E141" "Orphan rule_id count: $ORPHAN_RULES (rules thiếu trong SSOT)"

# T4 — Entity resolution (WARN only)
UNRESOLVED=$(jq -r --slurpfile ssot "$SSOT_MDM" \
  '[.signals[] | .affected_entities[]?] | unique
   | map(select(. as $e | ($ssot[0].master_entities | keys | index($e)) == null
                       and ($ssot[0].reference_data | keys | index($e)) == null))
   | length' "$LANE_DIR/signals.json")
[ "$UNRESOLVED" = "0" ] || log_warn "E045" "Unresolved entities count: $UNRESOLVED (có thể ngoài SSOT scope)"
```
