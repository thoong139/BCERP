## §A Header

Lane CD11 đảm bảo **tính nhất quán React component contracts** trong `apps/erp-web` — props type completeness, required flag accuracy, naming convention, orphan detection, duplicate name detection. Sub-stage 4.1 FE simplest lane (no SSOT mandatory).

**Vì sao quan trọng:**
- Props type `any` → runtime errors khi shape thay đổi
- Duplicate component name → import wrong instance → silent UI bug
- Orphan component → dead code accumulate → tech debt
- Naming inconsistency → friction cho developer (PascalCase vs kebab-case mixed)

```bash
FE_COMP_JSON=$(jq -c '.' "$FE_COMP_GRAPH")

EDGES=$(jq -c '.edges' "$FE_COMP_GRAPH")

log_phase_event "phase4_cd11" "INFO" \
  "{\"nodes\":$NODES_COUNT,\"edges\":$(jq '.edges | length' "$FE_COMP_GRAPH"),\"modules\":$(jq '.metadata.modules_covered | length' "$FE_COMP_GRAPH")}"
```

### Step CD11.2 — Props type completeness (INCOMPLETE_PROPS_TYPE)

> Mỗi props[] entry trong component node phải có `type` field không rỗng, không phải `any`/`unknown`.

**Logic:**
1. Iterate `nodes[]` filter `props[] | length > 0`
2. For each prop: check `type` field
   - Empty string OR `any` OR `unknown` → INCOMPLETE_PROPS_TYPE (severity SHOULD)
3. Build signal per component (gộp nhiều props vi phạm cùng component → 1 signal với evidence array)

**Signal payload:**
```json
{
  "kind": "INCOMPLETE_PROPS_TYPE",
  "severity": "SHOULD",
  "category": "VIOLATION",
  "rule_id": "FECC-CD11-001",
  "message": "Component CustomerCard có 2 props type không xác định (any/unknown)",
  "affected_entities": ["CustomerCard"],
  "affected_files": ["apps/erp-web/components/customer-card.tsx"],
  "evidence": [
    {"file": "apps/erp-web/components/customer-card.tsx", "prop": "onSelect", "type": "any"},
    {"file": "apps/erp-web/components/customer-card.tsx", "prop": "metadata", "type": ""}
  ],
  "suggested_action": "Define explicit types: onSelect: (id: string) => void; metadata: Record<string, unknown>."
}
```

### Step CD11.3 — Required flag accuracy (MISSING_REQUIRED_FLAG)

> Props có pattern "id|name|value|on*|data" thường required nhưng marked optional.

**Logic:**
1. Iterate props[] each node
2. Match prop name regex `^(id|.*Id|name|value|on[A-Z].*|data)$`
3. AND `required=false` AND `default_value=null`
4. → MISSING_REQUIRED_FLAG (severity MAY — chỉ gợi ý)

**Rule ID:** `FECC-CD11-002`

**Note:** Severity MAY vì heuristic — developer có thể intentionally optional (vd `onSelect` với default no-op).

### Step CD11.4 — Naming convention (PROP_NAMING_INCONSISTENCY)

> Component PascalCase, props camelCase, file kebab-case.

**Logic:**
1. Iterate nodes[]:
   - Component name không match `^[A-Z][a-zA-Z0-9]*$` → PROP_NAMING_INCONSISTENCY kind=component_name
   - File path basename (strip .tsx) không match `^[a-z][a-z0-9-]*$` → kind=file_name
2. Iterate props[] each node:
   - Prop name không match `^[a-z][a-zA-Z0-9]*$` → kind=prop_name (vd `Snake_Case`, `kebab-case`, `PascalCase`)
3. Severity SHOULD (convention enforcement)

**Rule ID:** `FECC-CD11-003`

**Skip:** Components trong `apps/erp-web/components/ui/` (shadcn/ui re-exports — keep external naming).

### Step CD11.5 — Orphan component detection (ORPHAN_COMPONENT)

> Component không được import bởi component khác AND không phải default export của page/layout.

**Logic:**
1. Build set of imported component names từ `edges[]` filter `kind=imports`
   - Each edge: `{from: importing_component_id, to: imported_component_id}`
2. Iterate `nodes[]`:
   - Component not in imported_set
   - AND file_path không match `app/**/page.tsx` hoặc `app/**/layout.tsx` (Next.js convention)
   - AND `default_export=true` (chỉ flag default exports — named export có thể là utility)
   - → ORPHAN_COMPONENT (severity MAY — dead code candidate, không cấm)

**Rule ID:** `FECC-CD11-004`

**Skip:** Components trong `apps/erp-web/components/index.tsx` (barrel re-export — không cần consumer trong graph).

### Step CD11.6 — Duplicate component name (DUPLICATE_COMPONENT_NAME)

> 2+ components cùng `name` ở khác `module` → import nhầm risk.

**Logic:**
1. Group `nodes[]` by `name`
2. Filter groups có count > 1 AND unique modules > 1
3. → DUPLICATE_COMPONENT_NAME (severity SHOULD)
4. Evidence: list tất cả file_path

**Rule ID:** `FECC-CD11-005`

**Skip:** Components trong `apps/erp-web/components/shared/` — explicit shared, expected reuse name.

### Step CD11.7 — Write signals.json (Atomic Write)

```bash
SIGNALS_TMP="$LANE_DIR/.signals.tmp.$$"

jq -n \
  --arg sid "$SESSION_ID" \
  --arg ts "$(date -Iseconds)" \
  --arg lane "CD11" \
  --arg agent "frontend-developer" \
  --arg scope_type "$SCOPE_TYPE" \
  --argjson signals "$ALL_SIGNALS_JSON" \
  --argjson modules_covered "$MODULES_COVERED" \
  --arg ci "$CI_SOURCE" \
  '{
    "$schema": "signals-v1",
    "session_id": $sid,
    "generated_at": $ts,
    "lane": $lane,
    "agent_subagent_type": $agent,
    "scope": {"type": $scope_type, "modules": $modules_covered},
    "status": "COMPLETED",
    "scan_duration_sec": ($scan_duration | tonumber),
    "signals": $signals,
    "metadata": {
      "signal_count": ($signals | length),
      "severity_breakdown": {
        "MUST": ([$signals[] | select(.severity == "MUST")] | length),
        "SHOULD": ([$signals[] | select(.severity == "SHOULD")] | length),
        "MAY": ([$signals[] | select(.severity == "MAY")] | length),
        "INFO": ([$signals[] | select(.severity == "INFO")] | length)
      },
      "category_breakdown": {
        "MISSING_INVARIANT": ([$signals[] | select(.category == "MISSING_INVARIANT")] | length),
        "VIOLATION": ([$signals[] | select(.category == "VIOLATION")] | length),
        "GAP": ([$signals[] | select(.category == "GAP")] | length),
        "RECOMMENDATION": ([$signals[] | select(.category == "RECOMMENDATION")] | length)
      },
      "modules_covered": $modules_covered,
      "ci_source": $ci,
      "fallback_used": false
    }
  }' > "$SIGNALS_TMP"

jq '.' "$SIGNALS_TMP" >/dev/null || die "E044" "signals.json invalid JSON"
mv "$SIGNALS_TMP" "$LANE_DIR/signals.json"
```

### Step CD11.8 — Write CD11 report (CORE-028, ≤15 dòng tiếng Việt)

```bash
N_SIGNALS=$(jq '.signals | length' "$LANE_DIR/signals.json")
N_MUST=$(jq '.metadata.severity_breakdown.MUST' "$LANE_DIR/signals.json")
N_SHOULD=$(jq '.metadata.severity_breakdown.SHOULD' "$LANE_DIR/signals.json")
N_MAY=$(jq '.metadata.severity_breakdown.MAY' "$LANE_DIR/signals.json")
N_INFO=$(jq '.metadata.severity_breakdown.INFO' "$LANE_DIR/signals.json")
COMPONENTS_CHECKED=$NODES_COUNT
LANE_COVERAGE_PCT=$(echo "scale=1; $COMPONENTS_CHECKED * 100 / $NODES_COUNT" | bc)

cat > "$LANE_DIR/CD11-fe-component-contracts-report.md" <<EOF
## Lane CD11 (FE Component Contracts) — $STATUS_PASS_FAIL

Thời gian: $STARTED_AT → $COMPLETED_AT (${DURATION_SEC}s)
Agent: frontend-developer

**Đã làm:** Quét $COMPONENTS_CHECKED React component trong apps/erp-web (modules: $(jq -r '.metadata.modules_covered | join(", ")' "$FE_COMP_GRAPH")) check props type completeness + required flag + naming convention + orphan + duplicate name. Source: fe-component-graph.json (Phase 2 Plugin #7).

**Kết quả:** $N_SIGNALS signals — MUST: $N_MUST, SHOULD: $N_SHOULD, MAY: $N_MAY, INFO: $N_INFO. Coverage cấp lane: ${LANE_COVERAGE_PCT}%. File đầu ra: signals.json + lane-status.json.

**Tiếp theo:** Orchestrator aggregate signals tại Phase 5 — coverage matrix gộp với 25 lanes còn lại.
EOF

LINE_COUNT=$(wc -l < "$LANE_DIR/CD11-fe-component-contracts-report.md")
[ "$LINE_COUNT" -le 15 ] || log_warn "E045" "CD11 report > 15 lines ($LINE_COUNT)"
```

### Step CD11.9 — Update lane-status.json (Atomic Write)

```bash

```

## §D POST-GATE (T1→T4 + Auto-Fix)

| Tier | Check | Tool | Fail action |
|------|-------|------|-------------|
| T1 | `signals.json` + `CD11-fe-component-contracts-report.md` + `lane-status.json` exist | bash | **E044** — Output missing → auto-fix (re-run Step CD11.7-CD11.9 max 3) |
| T2 | `signals.json` schema = `signals-v1`, `lane` = "CD11", all signals có `fingerprint` unique | jq | **E044** — Schema invalid → auto-fix re-build từ raw signals |
| T3 | Mọi signal `rule_id` match format `FECC-CD11-\d{3}` (FECC-CD11-001 → FECC-CD11-005) | jq | **E045** — Rule_id format invalid → re-render từ template |
| T4 | `affected_files[]` mỗi signal resolve được trong `fe-component-graph.json.nodes[].file_path` | jq | **E045** — File unresolved → log WARN (có thể là parsed component ngoài scope), KHÔNG block |

```bash
# T1 — Output files exist
for f in signals.json CD11-fe-component-contracts-report.md lane-status.json; do
  [ -f "$LANE_DIR/$f" ] || die "E044" "Output missing: $f"
done

# T2 — Schema valid
SCHEMA=$(jq -r '."$schema"' "$LANE_DIR/signals.json")
LANE_VAL=$(jq -r '.lane' "$LANE_DIR/signals.json")
[ "$SCHEMA" = "signals-v1" ] || die "E044" "Schema mismatch: $SCHEMA != signals-v1"
[ "$LANE_VAL" = "CD11" ] || die "E044" "Lane field mismatch: $LANE_VAL != CD11"

# Fingerprint dedup
FP_TOTAL=$(jq '.signals | length' "$LANE_DIR/signals.json")
FP_UNIQUE=$(jq '[.signals[].fingerprint] | unique | length' "$LANE_DIR/signals.json")
[ "$FP_TOTAL" = "$FP_UNIQUE" ] || die "E044" "Fingerprint collision: total=$FP_TOTAL unique=$FP_UNIQUE"

# T3 — Rule ID format
INVALID_RULES=$(jq -r '[.signals[] | select(.rule_id | test("^FECC-CD11-[0-9]{3}$") | not) | .rule_id] | length' "$LANE_DIR/signals.json")
[ "$INVALID_RULES" = "0" ] || die "E045" "Invalid rule_id format count: $INVALID_RULES"

# T4 — File resolution (WARN only)
UNRESOLVED=$(jq -r --slurpfile g "$FE_COMP_GRAPH" \
  '[.signals[] | .affected_files[]?] | unique
   | map(select(. as $f | ($g[0].nodes | map(.file_path) | index($f)) == null))
   | length' "$LANE_DIR/signals.json")
[ "$UNRESOLVED" = "0" ] || log_warn "E045" "Unresolved files count: $UNRESOLVED (có thể ngoài fe-component-graph scope)"
```

**Auto-fix budget (CORE-034):** Max 3 retries — re-render template + re-populate signals. Hết budget → ESCALATE FAIL.
