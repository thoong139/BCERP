## §A Header

Lane CD38 đo **độ phủ giữa BACKEND code và FRONTEND implementation** — phát hiện API endpoints user-facing không có FE caller, CRUD UI thiếu, permission catalog không có UI element, workflow state không có UI trigger. EUREKA-2026 có 90+ permissions + 17 modules + complex workflow logistics → CD38 critical để đảm bảo BE features có UI thực sự thấy được.

**Vì sao quan trọng (theo `ui-interactivity-spec.json` validation_rules):**
- `ORPHAN_API_ENDPOINT` (RULE-CD38-001, HIGH) → Endpoint deploy nhưng 0 FE caller → dead code hoặc gap implementation
- `WORKFLOW_STATE_NO_UI_TRIGGER` (RULE-CD38-002, CRITICAL) → State requires_user_action nhưng không UI → user bị block, workflow stuck
- `MISSING_PERMISSION_UI_ELEMENT` (RULE-CD38-003, HIGH) → Permission grant nhưng không UI render → user không thể exercise permission
- `INCOMPLETE_CRUD_UI` (RULE-CD38-004, MEDIUM) → Entity declare CRUD nhưng thiếu 1+ operation → partial implementation
- `MISSING_UI_FOR_USER_FACING_API` (RULE-CD38-006, MEDIUM) → Endpoint user_facing nhưng client KHÔNG được phép consume

### Step CD38.2 — Orphan API endpoint check (ORPHAN_API_ENDPOINT)

> Endpoint classified `user_facing` trong SSOT mà 0 FE caller sau grace period.

**Logic:**
1. Build set FE caller endpoints: `FE_CALLED_ENDPOINTS = jq '[.nodes[].endpoint_path] | unique' fe-api-client-graph.json`
2. Iterate `SSOT_ENDPOINT_CLS[]` filter `classification="user_facing"`
3. Endpoint không trong `FE_CALLED_ENDPOINTS` set:
   - Check `deployed_at` field — nếu < `GRACE_DAYS` ngày → skip (mới deploy, chưa đủ chứng cứ)
   - Check exclusions `exclusions.endpoints[]` — nếu match → skip
   - → ORPHAN_API_ENDPOINT (severity SHOULD, category VIOLATION)
4. Severity escalate MUST nếu endpoint có flag `business_critical=true` trong SSOT

**Signal payload:**
```json
{
  "kind": "ORPHAN_API_ENDPOINT",
  "severity": "SHOULD",
  "category": "VIOLATION",
  "rule_id": "UI-CD38-001",
  "ssot_rule_ref": "RULE-CD38-001",
  "message": "Endpoint GET /api/v1/crm/customer/{id}/preferences classified user_facing nhưng 0 FE caller (deploy >14 ngày trước)",
  "affected_entities": ["GET /api/v1/crm/customer/{id}/preferences"],
  "affected_files": ["apps/backend/Eureka.Modules.Crm/Customers/Queries/GetCustomerPreferencesQuery.cs"],
  "evidence": [{"file": ".mc-data/docs/_meta/ui-interactivity-spec.json", "snippet": "endpoint_classifications[] entry with classification=user_facing"}],
  "suggested_action": "Implement FE caller hook trong apps/erp-web/hooks/use-customer-preferences.ts HOẶC re-classify endpoint thành internal/deprecated"
}
```

### Step CD38.3 — Missing UI for user-facing API (MISSING_UI_FOR_USER_FACING_API)

> Endpoint user_facing có ý định cho client X (vd erp-web) nhưng client X KHÔNG được phép consume.

**Logic:**
1. Iterate `SSOT_ENDPOINT_CLS[]` filter `classification="user_facing"`
2. Get intended client từ `intended_clients[]` (vd ["erp-web", "mobile-customer"])
3. Cross-ref `client_specific.<client>.should_consume[]` (whitelist) trong SSOT
4. Endpoint không trong should_consume của client intended → MISSING_UI_FOR_USER_FACING_API (severity SHOULD)

**Rule ID:** `UI-CD38-002` (maps SSOT `RULE-CD38-006 client_specific_coverage_respect`)

**Note:** Severity SHOULD vì có thể do client_specific filter intentional (vd customer mobile chỉ cần subset). Suggested action: verify với BA owner intended_clients có khớp ý định không.

### Step CD38.4 — Incomplete CRUD UI check (INCOMPLETE_CRUD_UI)

> Entity declare CRUD nhưng thiếu UI page Create/Read/Update/Delete/List.

**Logic:**
1. Iterate `SSOT_CRUD_REQUIRED[]` entities (vd Customer, Product, Carrier, Invoice)
2. Cho mỗi entity, build expected paths theo convention SSOT.config:
   - List: `/{module}/{entity}` (vd `/crm/customer`)
   - Read: `/{module}/{entity}/[id]` (vd `/crm/customer/[id]`)
   - Create: `/{module}/{entity}/new` hoặc `/{module}/{entity}/create`
   - Update: `/{module}/{entity}/[id]/edit`
   - Delete: confirmation modal — heuristic check trong fe-component (DeleteButton component)
3. Cross-ref `fe-route-graph.nodes[].route_path` để verify expected paths tồn tại
4. Thiếu 1+ operation declared trong entity.operations[] → INCOMPLETE_CRUD_UI (severity MEDIUM)
5. Skip entities trong `SSOT_CRUD_OPTIONAL[]`
6. STRICT mode (default): mọi declared operation phải có UI; LENIENT mode: chỉ flag Create+Update+Delete (Read+List bắt buộc)

**Rule ID:** `UI-CD38-003` (maps SSOT `RULE-CD38-004 crud_required_must_be_complete`)

**Edge case:** Composite UI (vd modal create thay route /create) → cần component check trong fe-component-graph với pattern `Create{Entity}Modal`. v1.0 heuristic: nếu route Create không tồn tại nhưng entity có component `<{Entity}Modal>` → log WARN thay vì hard violation.

### Step CD38.5 — Missing permission UI element (MISSING_PERMISSION_UI_ELEMENT)

> Permission được grant cho role trong RBAC catalog nhưng KHÔNG có UI element render.

**Logic:**
1. Iterate `SSOT_PERM_MAPPING[]` entries (vd `{permission: "crm.customer.delete", ui_element_type: "button"}`)
2. Cross-ref `fe-permission-graph.nodes[]` filter `permission_key = SSOT.permission`
3. Nếu permission có ≥1 role grant trong `rbac-permission-catalog.json` (load nếu available) NHƯNG không có FE node:
   - → MISSING_PERMISSION_UI_ELEMENT (severity HIGH)
4. Check exclusions `exclusions.permissions[]` — skip nếu match

**Rule ID:** `UI-CD38-004` (maps SSOT `RULE-CD38-003 permission_must_have_ui_element`)

**Note:** Nếu RBAC SSOT chưa populated → fallback: chỉ flag permissions có declared `ui_element_type` trong `permission_ui_mapping[]`. Log INFO về RBAC SSOT missing nhưng KHÔNG die — graceful degrade.

### Step CD38.6 — Workflow state no UI trigger (WORKFLOW_STATE_NO_UI_TRIGGER)

> State workflow requires_user_action nhưng không có UI button/form tương ứng (severity CRITICAL — user bị block).

**Logic:**
1. Load `workflow-state-machines.json` (optional SSOT — nếu thiếu, fallback chỉ dùng `SSOT_WORKFLOW_ACTIONS`)
2. Iterate workflows[] → states[] filter `requires_user_action=true`
3. Cho mỗi state với user action declared, build expected UI trigger:
   - Action `submit_for_approval` → expect button `<SubmitForApprovalButton>` hoặc route `/order/[id]/approve`
   - Action `confirm_shipment` → expect button `<ConfirmShipmentButton>` hoặc form `/shipment/[id]/confirm`
4. Cross-ref `fe-component-graph.nodes[].name` (component pattern) HOẶC `fe-route-graph.nodes[].route_path` (route pattern)
5. Không tìm thấy → WORKFLOW_STATE_NO_UI_TRIGGER (severity MUST — block user)

**Rule ID:** `UI-CD38-005` (maps SSOT `RULE-CD38-002 workflow_user_action_must_have_ui`)

**EUREKA-specific:** Logistics workflow critical (shipment confirm, customs declaration submit, BOL signing) — thiếu UI trigger = supply chain stuck. Severity MUST hard-block deployment.

## §D POST-GATE (T1→T4 + Auto-Fix)

| Tier | Check | Tool | Fail action |

```bash
# T1
for f in signals.json CD38-ui-implementation-coverage-report.md lane-status.json; do
  [ -f "$LANE_DIR/$f" ] || die "E044" "Output missing: $f"
done

# T2
SCHEMA=$(jq -r '."$schema"' "$LANE_DIR/signals.json")
LANE_VAL=$(jq -r '.lane' "$LANE_DIR/signals.json")
[ "$SCHEMA" = "signals-v1" ] || die "E044" "Schema mismatch"
[ "$LANE_VAL" = "CD38" ] || die "E044" "Lane field mismatch"

FP_UNIQUE=$(jq '[.signals[].fingerprint] | unique | length' "$LANE_DIR/signals.json")
[ "$FP_TOTAL" = "$FP_UNIQUE" ] || die "E044" "Fingerprint collision"

# T3
INVALID_RULES=$(jq -r '[.signals[] | select(.rule_id | test("^UI-CD38-[0-9]{3}$") | not) | .rule_id] | length' "$LANE_DIR/signals.json")
[ "$INVALID_RULES" = "0" ] || die "E045" "Invalid rule_id format: $INVALID_RULES"

# T4 — SSOT ref resolution (WARN only)

  '[.signals[] | .ssot_rule_ref // empty] | unique
   | map(select(. as $r | ($ssot[0].validation_rules.rules | map(.id) | index($r)) == null))
   | length' "$LANE_DIR/signals.json")
[ "$UNRESOLVED_REF" = "0" ] || log_warn "E045" "Unresolved SSOT refs: $UNRESOLVED_REF"
```
