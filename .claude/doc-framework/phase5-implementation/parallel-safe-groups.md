## 1. Quy Tắc Parallel-Safe

Một nhóm features được coi là **Parallel-Safe** khi đáp ứng TẤT CẢ:

1. **Không có file EXCLUSIVE_WRITE chung** — không có 2 features cùng list 1 file ở mode EXCLUSIVE_WRITE
2. **Không phụ thuộc lẫn nhau** — Feature A không listed trong A2.3 Dependencies của Feature B (và ngược lại)
3. **Cùng layer hoặc layer trước đã hoàn thành** — Layer thấp hơn phải done trước
4. **Không có circular contract** — không cùng modify shared types/interfaces theo cách incompatible

## 4. Cross-Process Safety đã có

`wf-implement-feature` v3.2+ đã trang bị các cơ chế parallel-safe:

| Cơ chế | Mục đích |
|--------|----------|
| **Registry Mutex** (`.mc-data/docs/_meta/.registry.lock`) | Ngăn 2 sessions cùng ghi `req-registry.json` → lost write |
| **Per-Feature Lock** (`.mc-data/work/wf-implement-feature/.locks/[slug].lock`) | Ngăn 2 sessions cùng implement 1 feature |
| **Session-Log Append Lock** (`.session-log.lock`) | Ngăn corrupt JSON trong `_trace/session-log.json` |
| **Decision-Registry Lock** (`.decision-registry.lock`) | Ngăn lost decision entries |
| **CDG Cross-Session Aware** | Phase 3 file pre-check biết file đang được session khác ghi (qua lock) |

**Stale Detection:** Mọi lock có TIMEOUT 30s + stale-detection 5min (PID dead → auto cleanup).

## 6. Troubleshooting

| Triệu chứng | Nguyên nhân | Cách xử lý |
|-------------|-------------|-----------|
| `ERROR: Registry lock timeout` | Session khác đang ghi registry quá 30s | Chờ thêm hoặc check stale lock: `cat .mc-data/docs/_meta/.registry.lock` |
| `ERROR: Feature already locked by PID X` | Đã có session khác implement feature này | Dừng session đó hoặc dùng `--resume` từ session cũ |
| 2 sessions cùng modify file → conflict | Group không thực sự safe (check A2.4 sai) | Chạy sequential, báo lỗi để wf-plan-modules chạy lại |
| Lost write trên registry | Mutex bị bypass (skill cũ) | Update tất cả skills lên v3.2+ |
